一、安全性的含义与措施（识记）

识记 数据库安全性概念（与第 7 章完整性对照记忆）。
安全性（Security）：保护数据库防止不合法的使用造成数据泄露、篡改、破坏——防的是"坏人"（未经授权的用户）；完整性防的是"坏数据"（不符合语义的数据）。这是常考的一对辨析。
MySQL 提供的安全手段：①用户标识与鉴别（用户名＋口令＋主机）；②访问控制——自主存取控制 DAC（GRANT/REVOKE 授权）与强制存取控制 MAC；③视图机制（不同用户只见被授权的视图，见第 6 章）；④审计（记录操作日志）；⑤数据加密。

二、权限表：所在库与包含的表 ⭐

识记 权限表所在的数据库名、包含哪些表。
所有权限信息都存放在 mysql 这个系统数据库中（不是 information_schema！），常用六张权限表：
权限表级别存放内容
user全局级账号名、认证口令、连接资源限制，以及针对所有库的权限（Grant_priv 等）
db库级账号对某些数据库的操作权限（含 Host、Db 与各种 priv 列）
host库级（按主机）结合 db 表使用，规定某主机上某数据库的权限（老版本；MySQL 8.0 已不再使用该表，属了解）
tables_priv表级账号对具体表（含视图）的操作权限
columns_priv列级账号对具体列的 SELECT / INSERT / UPDATE / REFERENCES 权限
procs_priv子程序级存储过程与函数的 EXECUTE / ALTER ROUTINE 权限
🔑 记忆口诀："库（mysql）里有六表，从大到小 user → db → tables_priv → columns_priv，外加 host（按主机）与 procs_priv（按子程序）"。MySQL 8 还有 proxies_priv、role_db、default_roles 等角色相关表，答教材要求的六张即可。

三、用户管理四条语句 ⭐

识记 用户管理的操作及语句；简单应用 CREATE USER / DROP USER / RENAME USER / SET PASSWORD。
-- ① 创建用户（'用户'@'主机'；% 表示任意主机）
CREATE USER 'zhang'@'%' IDENTIFIED BY 'Abc@1234';
CREATE USER 'li'@'localhost' IDENTIFIED BY '123456';

-- ② 修改用户口令（SET PASSWORD 与 ALTER USER 两种写法都要认）
SET PASSWORD FOR 'zhang'@'%' = 'New@2026';
ALTER USER 'zhang'@'%' IDENTIFIED BY 'New@2026';   -- MySQL 8 推荐写法
SET PASSWORD = 'MyPwd';                              -- 改当前登录账号自己的口令

-- ③ 重命名用户（也可用来改主机限定）
RENAME USER 'zhang'@'%' TO 'zhangsan'@'192.168.1.%';

-- ④ 删除用户（只删账号，不影响它建的库表）
DROP USER IF EXISTS 'zhangsan'@'%';

-- 查看账号
SELECT user, host FROM mysql.user;
SHOW GRANTS FOR 'li'@'localhost';      -- 查看某账号已获得的全部权限
⚠️ 三个判分点：①账号永远写成 'user'@'host' 成对形式，只写用户名不规范；②口令在 MySQL 5.7.6+ 要用 IDENTIFIED BY '明文'（系统自动哈希），不要写 PASSWORD('…')（旧语法）；③手工改 mysql.user 表后必须执行 FLUSH PRIVILEGES; 才生效，用 CREATE USER 等语句则不需要。

四、权限的组类与权限级别值（领会）⭐

领会 可以授予的权限有几种类别（组类）及其含义；权限级别值的格式及其含义。
可授予权限的组类（按操作对象划分）：
组类典型权限含义
库（数据库）级权限ALTER、CREATE、DROP、INDEX、CREATE VIEW、SHOW VIEW、CREATE ROUTINE、LOCK TABLES、ALL [PRIVILEGES]、GRANT OPTION对整个库中所有对象的 DDL 类操作许可
表（对象）级权限SELECT、INSERT、UPDATE、DELETE、REFERENCES、TRIGGER、CREATE TEMPORARY TABLES对表/视图的 DML 类操作许可
列级权限SELECT(col)、INSERT(col)、UPDATE(col)、REFERENCES(col)只允许操作某表的指定列
子程序级权限EXECUTE、ALTER ROUTINE、CREATE ROUTINE、EVENT对存储过程 / 函数 / 事件的许可
管理类权限SUPER、PROCESS、RELOAD、SHUTDOWN、FILE、REPLICATION …服务器管理与运维操作（一般只给 DBA）
权限级别值（ON 后面写什么）：
写法级别含义
*.*全局级服务器上所有库、所有表（对应 mysql.user 表）
db_name.*库级指定库中的全部对象（对应 db 表）
db_name.tb_name表级指定库中的指定表/视图（对应 tables_priv）
db_name.routine_name子程序级指定的存储过程/函数
(列名) 跟在权限后列级SELECT(sname, sage) 只授这两列的查询权
🔑 由上到下一级比一级更细；ON *.* TO 是"全局授权"（往往要 DBA 权限才能给），ALL PRIVILEGES 指当前级别下所有静态权限，不含 GRANT OPTION（要让人能转授必须再写 WITH GRANT OPTION）。

五、GRANT 授予权限 ⭐⭐

简单应用 用 GRANT 语句授予权限。
-- 骨架：GRANT 权限[,权限…] ON 级别值 TO 用户@主机 [IDENTIFIED BY '口令'] [WITH GRANT OPTION];

① 库级：给 zhang 对 student_mgr 库所有表的查询、插入权限
GRANT SELECT, INSERT ON student_mgr.* TO 'zhang'@'%';

② 表级 + 允许转授
GRANT SELECT, UPDATE ON student_mgr.student TO 'li'@'localhost'
    WITH GRANT OPTION;

③ 列级：只允许查询和修改 sname、sage 两列
GRANT (SELECT(sname, sage), UPDATE(sname, sage))
    ON student_mgr.student TO 'wang'@'%';

④ 全局（所有库）+ 顺带建账号（IDENTIFIED BY 一起写）
GRANT ALL PRIVILEGES ON *.* TO 'dba'@'localhost' IDENTIFIED BY 'Pwd@2026'
    WITH GRANT OPTION;

⑤ 子程序级
GRANT EXECUTE ON PROCEDURE student_mgr.sp_avg TO 'li'@'localhost';
⚠️ MySQL 8 的两个变化：①GRANT 不再自动创建用户（5.7 可以），所以应先 CREATE USER 再授权，否则报 "Access denied for user …"；②给全局权限时 ON *.* 与 TO user 之间不能插库名。写答案时按教材的标准语法即可，但上机要记这两点。

六、REVOKE 撤销权限 ⭐

简单应用 用 REVOKE 语句撤销权限。
-- ① 撤销某项具体权限（对称于 GRANT）
REVOKE INSERT ON student_mgr.* FROM 'zhang'@'%';

-- ② 撤销全部权限（保留账号）
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'li'@'localhost';

-- ③ 只撤销"转授权利"
REVOKE GRANT OPTION FOR SELECT ON student_mgr.student FROM 'li'@'localhost';

-- ④ 撤销角色（MySQL 8，了解）
REVOKE reader_role FROM 'wang'@'%';

FLUSH PRIVILEGES;   -- 权限变更一般自动生效；手工改表时才必须刷
对比GRANTREVOKE
介词… TO 用户… FROM 用户（易错！）
撤销全部ALL PRIVILEGESALL PRIVILEGES, GRANT OPTION（要连转授权一起撤）
是否删账号—不删账号，只是收权；删账号用 DROP USER
级联WITH GRANT OPTION 允许被授权人再转授撤上级权限时，由他转授出去的权限一并失效（可用 CASCADE/RESTRICT 语义理解）
⚠️ 高频选择：REVOKE 用 FROM 不用 TO；GRANT OPTION 是"能否把权限再授予别人"的权限本身，撤掉后该用户转授给别人的权限也随之作废；DROP USER 会连带删掉该账号的所有 GRANT 记录。

七、本章速记小结

权限表在 mysql 库：user（全局）、db（库）、host（按主机）、tables_priv（表）、columns_priv（列）、procs_priv（子程序）。
用户四条：CREATE USER 'u'@'h' IDENTIFIED BY 'p' → SET PASSWORD FOR …=…（或 ALTER USER）→ RENAME USER … TO … → DROP USER。
权限五种组类：库级 DDL 类、表级 DML 类、列级、子程序级、管理类。
ON 的四种级别值：*.* 全局 ｜ db.* 库 ｜ db.tb 表 ｜ PROCEDURE/FUNCTION db.routine 子程序；列级在权限后用括号写列名。
GRANT … TO ｜ REVOKE … FROM；转授用 WITH GRANT OPTION，撤转授用 REVOKE GRANT OPTION FOR …。
手工改权限表后要 FLUSH PRIVILEGES；用语句改则不必。
安全性 vs 完整性：安全性防非法用户（泄露/篡改），完整性防非法数据（不符语义）。
