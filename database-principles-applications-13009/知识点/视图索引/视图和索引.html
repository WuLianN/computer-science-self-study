一、视图的含义与优点 ⭐

识记 视图的含义；领会 视图的优点。
视图（View）是虚拟表：它由一个 SELECT 语句（视图定义 / 子查询）导出，本身不存放数据，数据库中只保存视图的定义；每次通过视图查询时，DBMS 动态地从基表（导出视图所依赖的表）取值。视图可以与基本表一样进行查询，在一定条件下还能增删改。
视图＝"存起来的 SELECT"；数据永远只在基表里。（对应三级模式：视图 = 外模式）
视图的优点（简答模板）：①简化操作——把复杂的多表查询定义成视图，用户像查一张表一样使用；②提供一定程度的逻辑独立性——基表结构改变时可改视图定义，应用程序不必大改；③保护机密数据（安全性）——只让用户看到被授权的列/行；④为同一数据提供多种表现角度——不同用户看不同视图，方便重新组织数据；⑤便于数据共享与汇总统计。
⚠️ 易错：视图不占存储空间（只占极少存定义的空间）；把物化视图/索引视图（Oracle 的 MV、MySQL 需用汇总表模拟）与普通视图区分开——本课程讲的视图一律是不物化的虚视图。

二、视图四类操作 ⭐

识记 视图操作的内容；领会 CREATE / ALTER / DROP VIEW 及查询、更新视图的含义；简单应用 创建、修改、删除、查询视图。
-- ① 创建视图（可给视图的列起新名字，列数要与子查询一致）
CREATE VIEW v_math_stu AS
    SELECT sno, sname, sage FROM student WHERE sdept = '数学';

CREATE VIEW v_dept_age (系名, 平均年龄, 人数) AS
    SELECT sdept, AVG(sage), COUNT(*)
      FROM student GROUP BY sdept;

-- ② 修改视图定义（MySQL 8 支持；也可先 DROP 再 CREATE，或用 CREATE OR REPLACE VIEW）
ALTER VIEW v_math_stu AS
    SELECT sno, sname, sage, ssex FROM student WHERE sdept = '数学';

-- ③ 删除视图：只删定义，基表数据不受影响；可一次删多个
DROP VIEW IF EXISTS v_math_stu, v_dept_age;

-- ④ 查看视图结构 / 定义
SHOW TABLES;                        -- 视图与表列在一起
DESC v_math_stu;                    -- 看视图的列
SHOW CREATE VIEW v_math_stu;        -- 看视图的定义语句
🔑 用 DROP TABLE 删基表后，由它导出的视图会失效（查询报错），但视图定义仍留在数据字典里；用 DROP VIEW 删视图对基表毫无影响。这是常出的判断/选择题。

三、查询视图与更新视图 ⭐ 难点

领会 通过 SELECT 查询视图、更新视图的含义；简单应用 通过视图插入、删除、修改数据。
-- 查询视图：写法与查表一致，DBMS 会把它与视图定义"合并"成对基表的查询（视图消解）
SELECT * FROM v_math_stu WHERE sage < 20;
SELECT s.sname, g.grade FROM v_stu_score g JOIN student s ON s.sno = g.sno;
更新视图＝通过视图执行 INSERT / UPDATE / DELETE。DBMS 同样把它转换（消解）成对基表的操作，所以不是任何视图都能更新。
情形能否更新原因
视图由单个基表的部分行/列导出，且包含了主码列与 NOT NULL 列✅ 可增删改能唯一地把改动映射回基表的行
视图含聚合函数、GROUP BY、DISTINCT、UNION❌ 不可更新一行视图对应多行基表数据，无法逆映射
视图含多表连接（MySQL：一个可更新视图只能引用一张基表）❌ 一般不可无法确定改动落到哪张表
视图缺少基表的非空列❌ 插入失败插入时那些列没有值，违反 NOT NULL
INSERT INTO v_math_stu(sno, sname, sage) VALUES ('20210088','小周',19);
-- 实际向 student 表插入一行，但 sdept 没赋值 → 新行不满足 WHERE sdept='数学'，视图里看不到它

-- 加 WITH CHECK OPTION：通过视图做插入/修改时，强制新行仍满足视图的 WHERE 条件
CREATE VIEW v_math_stu AS
    SELECT sno, sname, sage, sdept FROM student WHERE sdept = '数学'
    WITH CHECK OPTION;                     -- 违约的操作会被拒绝（上面那条 INSERT 将失败）

UPDATE v_math_stu SET sdept = '物理' WHERE sno = '20210001';  -- ❌ 被 CHECK 拦下
DELETE FROM v_math_stu WHERE sno = '20210001';              -- ✅ 删除基表对应行
📝 简答模板（视图消解）：对视图的查询并不能直接从视图取数据（视图不存数据），DBMS 需先把对视图的查询与视图定义相结合、转换成等价的对基表的查询再执行，这个转换过程称为视图消解（View Resolution / 修改算法）。

四、索引的概念与分类（识记 / 领会）

识记 索引的概念与分类。
索引（Index）是对表中一列或多列值排序后建立的、用于加速存取的查找结构（MySQL 主要用 B+ 树），相当于书的目录：按索引找到指针再回表取数据。索引物理上独立于基表存储，由 DBMS 自动维护，对用户透明。
分类关键字特点
普通索引（常规索引）INDEX / KEY最基本的索引，允许重复值和 NULL，只为加速查询
唯一索引UNIQUE列值必须唯一，允许 NULL（可多个）
主键索引PRIMARY KEY唯一 + 非空，一张表只能有一个；InnoDB 中它就是聚簇索引（叶子结点存整行数据）
全文索引FULLTEXT针对 CHAR/VARCHAR/TEXT 的大文本检索，配合 MATCH … AGAINST
空间索引SPATIAL用于地理空间数据类型
组合（多列）索引INDEX(col1, col2)遵循最左前缀原则：只用到 col2 时索引不生效
使用索引的优点（领会）：大大加快查询速度（尤其是选择、连接、排序、分组操作）；保证数据唯一性（唯一/主键索引）；加快表间连接；帮助优化器避免排序。代价：①索引占物理存储空间；②表增删改时 DBMS 要额外维护索引，降低写效率；③建立索引本身耗时。

五、建立索引的建议 ⭐ 简答

领会 建立索引的建议。
✔ 适合建索引的列
  • 作为主键 / 外键的列
  • 常出现在 WHERE、ON、连接条件中的列
  • 常用于 ORDER BY、GROUP BY、DISTINCT 的列
  • LIKE 的前缀匹配列（'abc%'）
  • 列的取值范围大（选择性高）、表大且读多写少
✘ 不宜建索引的列
  • 很少查询的列、很少出现在条件中的列
  • 取值极少的列（如性别，只有两个值）
  • 频繁更新的列；小表（全表扫描更快）
  • TEXT / BLOB 列、长字符串列（只能前缀索引）
  • 视图中一般不单独建索引（视图上不能建索引）

六、索引操作：三建、两删、一看 ⭐

识记 三种创建索引的方法；领会 两种删除索引的方法；简单应用 CREATE INDEX / ALTER TABLE 建索引、SHOW INDEX 查看、DROP INDEX / ALTER TABLE 删除。
-- ========== 三种创建方法 ==========
-- ① 用 CREATE INDEX 单独创建（最常用）
CREATE INDEX idx_sname ON student (sname);
CREATE UNIQUE INDEX uk_email ON student (email);        -- 唯一索引
CREATE INDEX idx_dept_age ON student (sdept DESC, sage); -- 组合索引（可指定降序）

-- ② 用 ALTER TABLE 创建
ALTER TABLE student ADD INDEX idx_sname (sname);
ALTER TABLE student ADD UNIQUE uk_email (email);
ALTER TABLE student ADD PRIMARY KEY (sno);           -- 加主键即建主键索引

-- ③ 创建表的同时定义索引
CREATE TABLE sc (
  sno CHAR(8), cno CHAR(3), grade SMALLINT,
  PRIMARY KEY(sno, cno),           -- 主键索引
  UNIQUE uk_g (cno, grade),         -- 唯一索引
  INDEX idx_grade (grade)           -- 普通索引
);

-- ========== 查看 ==========
SHOW INDEX FROM student;            -- 列出该表所有索引（Seq_in_index、Cardinality 等）

-- ========== 两种删除方法 ==========
DROP INDEX idx_sname ON student;                    -- 方式一：DROP INDEX 名 ON 表名（MySQL 特有语法）
ALTER TABLE student DROP INDEX idx_sname;            -- 方式二：ALTER TABLE ... DROP INDEX
ALTER TABLE student DROP PRIMARY KEY;                -- 删主键索引（见第 7 章）
⚠️ 三个细节：①索引名与列名是两回事——idx_sname (sname) 中前者是索引名，可省略让系统用列名当索引名；②DROP INDEX 必须写 ON 表名，因为索引不属于独立对象；③主键索引不能只删索引不删约束，用 ALTER TABLE ... DROP PRIMARY KEY。另：视图上不能创建索引。

七、本章速记小结

视图三句话：虚表不存数据、只存 SELECT 定义；视图＝外模式；查询要走"视图消解"转成对基表的查询。
视图四操作：CREATE VIEW（可给列名）→ ALTER VIEW → SHOW CREATE VIEW / DESC → DROP VIEW。
可更新视图条件：来自单表、含主码与非空列、无聚合/分组/DISTINCT/UNION；要限制"插入的行必须还看得见"就加 WITH CHECK OPTION。
索引五类：普通、唯一、主键（唯一+非空、每表仅 1 个、InnoDB 聚簇）、全文、空间；组合索引按最左前缀生效。
索引三建：CREATE INDEX / ALTER TABLE ADD INDEX / CREATE TABLE 内写 INDEX(...)；两删：DROP INDEX 名 ON 表 / ALTER TABLE DROP INDEX 名；一看：SHOW INDEX FROM 表。
建索引的原则：大表、常作条件/排序、选择性高的列建；小表、频繁更新、取值少的列不建——索引提速查询、拖累更新、消耗空间。
