一、理论概述：怎么算"好"的关系模式

识记 关系数据库设计理论的概念、该理论包含的内容；领会 各内容之间的关系、如何判断一个关系模式的好坏。
关系数据库设计理论（规范化理论）研究的核心问题是：如何把一个"不好"的关系模式改造成"好"的关系模式，即如何构造无冗余、无插入/删除/修改异常的关系模式集合。它包含三大块内容：
内容解决什么问题与其他内容的关系
函数依赖（含多值依赖）描述属性之间固有的约束，是衡量工具是定义范式、公理系统的基础
范式（1NF~4NF）给出关系模式好坏的等级标准用依赖来定义，是规范化的目标
模式分解（规范化方法）把低一级模式拆成高一级模式的算法分解要求无损连接、保持函数依赖
判断一个关系模式好不好的四条标准（简答）：①数据结构简单、清晰；②数据冗余小；③不出现插入异常、删除异常、修改异常；④符合语义、易于理解。
⚠️ 反直觉但必考：范式越高不一定越好。规范化过头会导致关系过多、查询时要大量连接，性能下降。实际设计通常做到 3NF 即可，必要时故意"反规范化"（冗余存储）来提速。

二、函数依赖：完全、部分、传递 ⭐⭐

识记 数据依赖的类型和含义；领会 函数依赖、完全函数依赖、部分函数依赖、传递函数依赖的含义。
数据依赖：一个关系内部属性值之间应满足的约束条件，反映属性间的相互依赖关系，主要包括函数依赖（FD）和多值依赖（MVD）两类（还有连接依赖等）。它是"不好好设计就会出问题"的根源。
函数依赖 FD：设 R(U) 是属性集 U 上的关系模式，X、Y ⊆ U。对 R 的任一具体关系 r，若不可能存在两条元组在 X 上值相等而在 Y 上值不等，则称 X 函数决定 Y，记作 X → Y。X 叫决定因素，Y 叫依赖因素。
通俗记法：知道了 X 的值，就唯一确定了 Y 的值（如学号 → 姓名）。
名称定义（关键条件）例子（码为 (Sno,Cno)）
完全函数依赖
X →f Y		X → Y，且 X 的任何一个真子集 X′ 都不能决定 Y（X 中一个属性都不能少）(Sno, Cno) →f Grade：只有同时知道学号和课程号才能确定成绩
部分函数依赖
X →p Y		X → Y，但 Y 依赖于 X 的某一部分（存在真子集 X′ 使 X′→Y 成立）(Sno, Cno) →p Sname：单靠 Sno 就能定姓名 → 2NF 要消灭它
传递函数依赖
X →t Y		X → Y 是通过 X → Z、Z → Y 传过去的，且 Z ↛ X（Z 不能决定 X，即 Z 不是候选码）Sno → Dept、Dept → Dloc ⇒ Sno →t Dloc → 3NF 要消灭它
平凡 / 非平凡函数依赖若 Y ⊆ X 则称 X → Y 为平凡的（恒成立、无研究价值）；否则为非平凡的。讨论的都是非平凡依赖(Sno,Cno) → Sno 是平凡的
多值依赖 X →→ Y对 X 的每个值，有一组相互独立的 Y 值与之对应，且这组值只由 X 决定、与剩余属性 Z 无关（Y 与 Z 彼此独立）教师 Tno 教多门课 Cno、多用本教材 Bookno：Cno 与 Bookno 互不影响 ⇒ Tno →→ Cno
🔑 函数依赖 vs 多值依赖：FD 要求"唯一确定"（一对一/多对一的映射感觉），MVD 是"确定一组且这组与其余属性无关"（一对多、且两边独立）。MVD 是 FD 的推广：X → Y 成立时必有 X →→ Y 成立，反之不真。
⚠️ 传递依赖的坑：若 X → Z 且 Z → Y，但 Z → X 也成立（Z 与 X 互为候选码），则 X → Y 是直接依赖而非传递依赖。定义里那句"Z ↛ X"就是为排除这种情况。

三、码与五级范式 1NF → 4NF ⭐⭐

识记 码的含义、范式的含义；领会 1NF/2NF/3NF/BCNF/4NF 与多值依赖的含义。
码（Key）的四个概念先分清：
术语定义
超码（超键）能唯一标识元组的属性（组）。(Sno, Sname) 也是超码
候选码最小的超码——去掉任何一个属性就不再唯一。一个关系可有多个候选码
主码（主键）由设计者从候选码中选定一个用来标识元组的
主属性 / 非主属性包含在任一候选码中的属性为主属性；其余为非主属性（注意：不是"在主码中"才算主属性）
五级范式（层层加严，低范式是高范式的必要不充分条件）：
范式定义（在原子上加什么条件）消灭了什么口诀
1NF关系 R 的每个分量都是不可再分的数据项（原子性）——所有关系模式默认都满足 1NF非原子值（重复组、多值列）列不分
2NFR ∈ 1NF，且每一个非主属性都完全函数依赖于候选码非主属性对码的部分依赖不留半截依赖
3NFR ∈ 2NF，且每一个非主属性都不传递函数依赖于候选码非主属性对码的传递依赖非主属性不靠"中间人"
BCNFR ∈ 1NF，且每一个函数依赖 X → Y（Y ↄ X）的决定因素 X 必含有候选码（X 是超码）主属性对码的部分/传递依赖、决定因素不含码的依赖每个决定因素都是码
4NFR ∈ 1NF，若存在非平凡函数依赖 X → Y，则 X 必含候选码；即允许非平凡多值依赖存在但决定因素必须含码非主属性对码的多值依赖连多值依赖也不许
高范式一定满足低范式；不满足高层时，只能退回低一层作答
三种异常（简答常与"规范化目的"一起问）：
  1. 插入异常：应插入的信息因缺少主码而插不进去（如新系还没招学生，就录不进该系的地点）。
  2. 删除异常：删除某信息时连带删掉了不该删的（最后一名学生退学，该系的信息随之消失）。
  3. 修改（更新）异常：同一信息多处冗余，改一处漏一处导致数据不一致（改系地址要改所有学生记录）。

四、规范化的目的、原则与方法 ⭐ 简答必背

领会 规范化的目的、方法和过程；综合应用 用 1NF/2NF/3NF 的规范化方法解决应用问题。
目的：解决关系模式中存在的数据冗余和插入、删除、修改异常——通过分解关系模式，使每个关系模式"一对主题、一件事"，达到所需的范式（通常 3NF）。
基本原则（"一事一地"）：一个关系模式只描述一个实体或一种联系，即每个非主属性都直接、完全依赖于候选码；一个基本表不要既谈学生又谈系部。分解时要尽量保证①无损连接（分解后自然连接能还原原关系，不丢信息）、②保持函数依赖（原依赖集在分解后的各模式上仍能全部推出，不必跨表检查）。
过程（逐步升范式，考试按这三步写）：
  1. 先保证 1NF：把重复组、多值列拆成独立的行/列（属性原子化）。
  2. 升到 2NF：找出候选码，把部分依赖 X′ → Y（X′ ⊂ 码）单独成表——决定因素当主码，Y 跟着它走；原表只保留对码的完全依赖。
  3. 升到 3NF：把传递依赖 Z → Y（Z 非码）单独成表——Z 作主码，Y 放它那张表；原表保留 Z 作外码即可。
  4. （若还要升 BCNF）对每一个决定因素不含码的依赖 X → Y，都以 X 为主码拆出新表，并在原表保留 X。
🔑 拆表的机械口诀：看到 A → B 且 A 不是候选码 → 就拆成"AB 一张表（A 作主码）"＋"原表去掉 B"。反复做，直到每个决定因素都是码 ⇒ BCNF；只做非主属性的部分/传递依赖 ⇒ 3NF 就够。

五、Armstrong 公理与属性集闭包 ⭐

识记 Armstrong 公理系统的含义；领会 闭包及其计算；简单应用 确定候选码。
Armstrong 公理系统：给定函数依赖集 F，用来推出 F 所逻辑蕴含的全部依赖（F 的闭包 F⁺）的一组推理规则，它既是正确的（推出的都成立）又是完备的（凡成立的都能推出）。三条公理：
公理形式直觉
自反律若 Y ⊆ X ⊆ U，则 X → Y 成立大的决定它包含的（平凡依赖）
增广律若 X → Y，且 Z ⊆ U，则 XZ → YZ 成立两边同时加属性，依赖不变
传递律若 X → Y、Y → Z，则 X → Z依赖可以接力
三条推论（由公理导出，选择题会考"哪条不是公理"）：合并规则（X→Y、X→Z ⇒ X→YZ）；分解规则（X→YZ、Z⊆Y ⇒ X→Z）；伪传递规则（X→Y、WY→Z ⇒ XW→Z）。
属性集闭包 X+：在 F 存在下，由 X 能函数决定的全部属性的集合。判定利器：
① X → Y 成立 ⇔ Y ⊆ X+；　② X 是超码 ⇔ X+ = U；　③ X 是候选码 ⇔ X+ = U 且 X 的任何真子集闭包都 ≠ U。
闭包计算算法：令 X⁽⁰⁾ = X；反复把 F 中左部已包含于当前集合的那些依赖的右部并进来，直到集合不再增大。
例1  R(A,B,C,D)，F = { A→B, B→C, A→D }，求 A⁺ 并判断候选码
   X⁽⁰⁾ = {A}
   A→B 左部 A ⊆ {A} ⇒ X⁽¹⁾ = {A,B}
   B→C 左部 B ⊆ {A,B} ⇒ X⁽²⁾ = {A,B,C}
   A→D 左部 A ⊆ {A,B,C} ⇒ X⁽³⁾ = {A,B,C,D} = U，且不再增大
   ∴ A⁺ = U ⇒ A 是超码；A 是单属性、无真子集 ⇒ A 是唯一的候选码

例2  R(Sno,Cno,Grade,Credit)，F = { (Sno,Cno)→Grade, Cno→Credit }，求候选码
   分类：只在左边出现 = {Sno}；只在右边出现 = {Grade, Credit}；两边都出现 = {Cno}
   ⇒ 候选码必含 Sno，必不含 Grade/Credit，再按需补 Cno
   (Sno)⁺ = {Sno} ≠ U（推不出任何东西）
   (Sno,Cno)⁺ = {Sno,Cno} →Grade →Credit = U  ⇒ 唯一候选码 (Sno, Cno)
求候选码三步快捷法（先分类再验闭包，比全排列快得多）：
  1. 把属性按在 F 中出现位置分四类：L（只在左）、R（只在右）、LR（左右都出现）、N（两边都不出现）。
  2. L 类和 N 类属性必属于任何候选码；R 类属性必不属于任何候选码。
  3. 求 (L∪N)+：若 = U，它就是唯一候选码；若 ≠ U，再依次加入 LR 类属性（一个、两个……）求闭包，凡是闭包 = U 且已最小的都是候选码。
📝 若题目只让"分析关系模式的主码"，写答案时补一句依据：因为 X 能决定全部属性且去掉任一属性后不能再决定全部属性，所以 X 是候选码，取为主码——踩点给分。

六、综合例题：一步步分解到 3NF ⭐⭐

综合应用 综合运用依赖、范式、分解方法解决设计问题（大题模板）。
题目：关系模式 SCK(Sno, Sname, Dept, Dloc, Cno, Cname, Grade)，语义：每个学生属于一个系、每个系只有一个坐落地，每门课有唯一课名，一个学生选一门课有一个成绩。已知函数依赖集
F = { Sno → Sname, Sno → Dept, Dept → Dloc, Cno → Cname, (Sno, Cno) → Grade }
请：① 求候选码；② 写出存在部分依赖与传递依赖的属性；③ 判断它最高属于第几范式并说明理由；④ 分解到 3NF。
  1. 求候选码。按出现位置分类：L 类（只在左）= {Sno}；R 类（只在右）= {Sname, Dloc, Cname, Grade}；LR 类（左右都有）= {Dept, Cno}。⇒ 候选码必含 Sno、必不含 R 类四个属性。 单靠 Sno 推不出 Cname、Grade，故需补 LR 类；求 (Sno,Cno)+：由 F 依次得 Sname、Dept、Dloc、Cname、Grade ⇒ 闭包 = 全属性 U，且去掉 Sno 或 Cno 都不能决定 Grade， ∴ 候选码 = (Sno, Cno)，取为主码。主属性 {Sno, Cno}，非主属性 {Sname, Dept, Dloc, Cname, Grade}。
  2. 列出违反 2NF 的部分依赖。Sno → Sname、Sno → Dept（决定因素只是码的一部分）；Cno → Cname 同理。⇒ Sname、Dept、Cname 部分依赖于码。
  3. 列出违反 3NF 的传递依赖。Sno → Dept、Dept → Dloc 且 Dept ↛ Sno ⇒ Dloc 传递依赖于码。
  4. 判定范式。属性全为原子值 ⇒ 满足 1NF；但存在非主属性对码的部分依赖 ⇒ 不满足 2NF。故 SCK 最高属于 1NF。
  5. 存在的问题（按异常答）。数据冗余大（姓名随选课次数重复、系址随每个学生重复）；插入异常（新专业/新系尚无选课记录时，Dept、Dloc 因主码 Sno·Cno 为空而插不进去）；删除异常（删掉某生全部选课记录会连带删掉他的学籍信息）；修改异常（系址搬迁需改所有相关行，易不一致）。
  6. 分解。把部分依赖、传递依赖的"决定因素＋其依赖属性"各自独立成表，原表只留对码的完全依赖： 
    -- 消除部分依赖（→2NF）后，再消除传递依赖（→3NF），最终得到四个关系：
学生 (Sno, Sname, Dept)              -- 码 Sno；Dept 为外码，Sno→Dept 是完全依赖
院系 (Dept, Dloc)                     -- 码 Dept；把 Sno→Dept→Dloc 的传递链切断
课程 (Cno, Cname)                     -- 码 Cno
选课 (Sno, Cno, Grade)                -- 码 (Sno,Cno)；只留完全依赖 Grade
-- 检查：每个决定因素都是所在表的码，非主属性既不部分也不传递依赖码
--       ⇒ 已达 3NF（此例同时满足 BCNF）
-- 分解无损：连接键 Sno / Dept / Cno 均为相关表的主码
--       ⇒ 自然连接可还原原关系，且保持了全部函数依赖
🔑 另一个高频小问："判断下列模式各属于第几范式"——答题格式固定为"① 候选码是 X；② 所有非主属性完全/传递依赖情况；③ 所以属/不属 几 NF"。特别注意 BCNF 与 3NF 的分界：只要出现决定因素不含候选码的依赖（典型如 (Sno,Cno)→Teacher 与 Teacher→Cno 并存），就只到 3NF 不到 BCNF。

七、本章速记小结

五条一句话：
  1. 依赖是尺子：完全/部分/传递 FD 看非主属性与码的关系，MVD 看独立的一组值。
  2. 范式是等级：1NF 列不分 → 2NF 去部分 → 3NF 去传递 → BCNF 决定因素必含码 → 4NF 去多值依赖。
  3. 规范化＝分解：见 A→B 且 A 不是码，就把 A＋B 拆一张表，A 作主码。
  4. 求码靠闭包：L/N 类必入选，R 类必出局，剩下补 LR 类逐个验 X+ = U。
  5. Armstrong 三公理：自反、增广、传递（合并/分解/伪传递是推论，不是公理）。
