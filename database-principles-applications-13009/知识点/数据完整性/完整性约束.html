一、概述：完整性与约束机制（识记 / 领会）

识记 数据完整性的概念、约束机制的优点；领会 MySQL 支持的完整性类型及各约束的含义。
数据完整性（Data Integrity）：数据库中数据的正确性、有效性和相容性——防止不符合语义（错误、无效）的数据被输入或输出，从而保证数据库里的数据与现实世界的约束一致。
约束机制的优点（简答）：完整性规则以数据库对象（约束）的形式定义并存储在数据字典中，由 DBMS 自动检查并强制执行，因此①无须在应用程序中重复编写检查代码，简化程序；②集中定义、修改方便（改约束即可，不必改所有程序）；③检查效率高、更可靠，避免人为绕过；④规则与数据一起存储、随表存在，不会失效。
MySQL 完整性类型对应约束约束的含义（保证什么）
实体完整性PRIMARY KEY、UNIQUE每一行都能被唯一标识：主码非空且不重复
参照完整性FOREIGN KEY表间关系有效：外码值要么为空，要么在被参照表中确实存在
用户定义的完整性CHECK、NOT NULL、DEFAULT、数据类型与长度满足具体应用的语义要求（取值范围、非空、枚举值）
⚠️ MySQL 特有的坑：CHECK 约束在 8.0.16 之前会被解析但直接忽略（不生效）；MyISAM 引擎不支持外键——只有 InnoDB 才真正实施这些约束。答题按"支持"的标准 SQL 语义写，但实操时记着版本与引擎。

二、实体完整性：主键约束与唯一性约束 ⭐

领会 主键约束、唯一性约束的含义及区别；综合应用 在设计中正确使用语句实现实体完整性。
实体完整性规则：若属性 A 是基本关系的主属性（属于某个候选码），则 A 不能为空——即主码的取值唯一且非空，保证每个元组可区分。
对比项PRIMARY KEY（主键约束）UNIQUE（唯一性约束）
取值唯一✅✅
允许 NULL❌ 绝不允许✅ 允许（MySQL 中可存在多个 NULL）
一张表能有几个只能 1 个可以多个
作用唯一标识实体（行的身份证）保证某列值不重复（如手机号、邮箱）
物理实现InnoDB 中是聚簇索引，表数据按它组织非聚簇的唯一索引
能否被外键参照通常被参照（标准 SQL 要求主码）MySQL 也允许被外键参照
-- 建表时定义
CREATE TABLE student (
  sno  CHAR(8)  PRIMARY KEY,          -- 列级：单列主键
  sname VARCHAR(20) NOT NULL,
  email VARCHAR(30) UNIQUE,           -- 唯一性约束
  idcard CHAR(18) UNIQUE
);
CREATE TABLE sc (
  sno CHAR(8), cno CHAR(3), grade SMALLINT,
  CONSTRAINT pk_sc PRIMARY KEY (sno, cno),   -- 多列主键必须写成表级，可给约束名
  CONSTRAINT uk_sc UNIQUE (sno, cno)          -- 组合唯一性约束
);

-- 事后用 ALTER TABLE 追加 / 删除
ALTER TABLE student ADD CONSTRAINT pk_sno PRIMARY KEY (sno);
ALTER TABLE student ADD CONSTRAINT uk_mail UNIQUE (email);
ALTER TABLE student DROP PRIMARY KEY;              -- 删主键（主键不用写约束名）
ALTER TABLE student DROP INDEX uk_mail;            -- 删唯一约束＝删它对应的唯一索引
📝 简答模板（区别）：两者都要求列值不重复。主键约束额外要求非空、一张表只能定义一个，用于唯一标识元组，且可作为外键被参照的规范目标；唯一性约束允许空值（可多个 NULL）、一张表可定义多个，只用于保证某列（组）取值不重复。

三、参照完整性：外键的六条规则 ⭐

识记 定义外键时必须遵守的规则；领会 参照完整性规则与外键约束的含义。
参照完整性规则：若属性（组）F 是基本关系 R 的外码，它与基本关系 S 的主码 K 相对应，则 R 中每个元组在 F 上的值必须或者取 NULL（F 中每个属性都取空值）、或者等于 S 中某个元组的主码值。
外键把两张表"钉"在一起：允许的取值 = 被参照表主键的现有值 ∪ {NULL}
定义外键必须遵守的规则（识记，多选/简答）：
  1. 外键所在的参照表与被参照表必须是存在的表：先建被参照（父）表，再建参照（子）表；删除时顺序相反（先删子表）。
  2. 外键列与被参照列的数据类型必须相容（可以转换）。
  3. 被参照的列必须是主键或唯一键（保证能被唯一定位）。
  4. 外键列名可以与被参照列名不同，但含义（域）要一致。
  5. 外键列的取值必须为空或等于被参照表中某行主键值。
  6. 只有 InnoDB 引擎支持外键；外键列会自动创建索引，被参照列也必须有索引。

四、外键约束的创建、修改、删除（简单应用）

简单应用 用 SQL 语句创建、删除和修改外键约束；综合应用 设计中实现参照完整性。
-- ① 建表时创建外键
CREATE TABLE sc (
  sno CHAR(8), cno CHAR(3), grade SMALLINT,
  CONSTRAINT fk_sc_stu FOREIGN KEY (sno) REFERENCES student (sno)
        ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT fk_sc_course FOREIGN KEY (cno) REFERENCES course (cno)
        ON DELETE SET NULL            -- 课程被删则把该列置空（要求列可为 NULL）
);

-- ② 事后追加外键（结构与 ① 中的表级写法一致）
ALTER TABLE sc ADD CONSTRAINT fk_sc_stu
    FOREIGN KEY (sno) REFERENCES student (sno);

-- ③ 删除外键约束（必须写约束名，MySQL 中不能只写列名）
ALTER TABLE sc DROP FOREIGN KEY fk_sc_stu;
ALTER TABLE sc DROP KEY fk_sc_stu;               -- 等价写法（同时删掉它建的索引）

-- ④ "修改"外键：MySQL 没有 ALTER ... MODIFY FOREIGN KEY，须先删后加
ALTER TABLE sc DROP FOREIGN KEY fk_sc_stu;
ALTER TABLE sc ADD CONSTRAINT fk_sc_stu FOREIGN KEY (sno)
    REFERENCES student (sno) ON DELETE SET NULL;

-- ⑤ 临时关闭 / 恢复外键检查（导入数据时用，了解）
SET FOREIGN_KEY_CHECKS = 0;   SET FOREIGN_KEY_CHECKS = 1;
级联动作含义（当父表行被 DELETE / 主键被 UPDATE 时）
CASCADE连锁处理：子表中相应行一起删除 / 外码值一起改成新值
SET NULL把子表的外码置为 NULL（该列必须允许空）
RESTRICT / NO ACTION拒绝父表的删除/修改操作（默认动作）——子表还有引用就不许动
SET DEFAULT置为默认值（标准 SQL 有，MySQL 不支持）
⚠️ ON DELETE 与 ON UPDATE 要分别声明，只写一个则另一个用默认 RESTRICT。自建外键时约束名（CONSTRAINT 名字）要记住——删除时只能按名字删；不写名字的话 MySQL 自动生成，可通过 SHOW CREATE TABLE sc 查到。

五、用户定义完整性：CHECK 与非空约束（识记 / 领会）

识记 检查约束和非空约束的含义；领会 实现用户定义完整性可以使用的语句。
非空约束 NOT NULL：该列不允许取空值，插入或修改时必须给值（且不能显式赋 NULL）。默认允许为空。 检查约束 CHECK (条件表达式)：把具体的语义约束写成布尔表达式，插入/修改的值必须使表达式为真，否则拒绝（值使表达式为 UNKNOWN 也视为通过，这是 SQL 标准的三值逻辑特性）。 
-- 建表时声明
CREATE TABLE student (
  sno   CHAR(8)  NOT NULL PRIMARY KEY,
  sname VARCHAR(20) NOT NULL,
  sage  SMALLINT CONSTRAINT ck_age CHECK (sage BETWEEN 15 AND 50),
  ssex  CHAR(2)  CHECK (ssex IN ('男','女')),
  dept  VARCHAR(20) DEFAULT '计算机'       -- 默认值约束
);
CREATE TABLE sc (
  sno CHAR(8), cno CHAR(3), grade SMALLINT,
  CONSTRAINT ck_grade CHECK (grade >= 0 AND grade <= 100)   -- 表级检查约束
);

-- 事后增删
ALTER TABLE student ADD CONSTRAINT ck_name CHECK (CHAR_LENGTH(sname) >= 2);
ALTER TABLE student DROP CHECK ck_name;                 -- 删检查约束
ALTER TABLE student MODIFY sname VARCHAR(20) NOT NULL;   -- 加非空约束
ALTER TABLE student MODIFY sname VARCHAR(20) NULL;       -- 取消非空约束
ALTER TABLE student ALTER COLUMN sage SET DEFAULT 20;
🔑 非空与 CHECK 的分工："这一列必须有值"用 NOT NULL；"这一列的值要满足什么条件"用 CHECK；"没给值时默认填什么"用 DEFAULT；"取值只能是有限几个"还可选择 ENUM('男','女') 类型（属用户定义完整性靠数据类型实现的思路）。MySQL 没有 ALTER TABLE ... DROP NOT NULL，取消非空要用 MODIFY 重写列定义。

七、本章速记小结

三条规则 → 四类约束：实体→PRIMARY KEY / UNIQUE；参照→FOREIGN KEY；用户定义→CHECK / NOT NULL / DEFAULT。
主键 vs 唯一：主键非空、只能一个、标识行；唯一可有 NULL、可以多个。
外键六条规则：父表先建子表后建（删相反）、类型相容、被参照列必须主键或唯一、列名可不同、取值须为空或存在于父表、只有 InnoDB 支持。
级联动作：CASCADE 连锁 / SET NULL 置空 / RESTRICT·NO ACTION（默认）拒绝。
删约束的名字差异：主键不写名（DROP PRIMARY KEY）、唯一约束按索引名删、外键与检查约束按约束名删。
修改外键＝先 DROP 再 ADD；MySQL 8.0.16 之前 CHECK 不生效，MyISAM 不认外键。
