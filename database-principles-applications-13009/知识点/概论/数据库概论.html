一、DB / DBMS / DBS 三个概念 ⭐

识记 数据库 DB、数据库管理系统 DBMS、数据库系统 DBS 的概念。
缩写全称一句话定义
DBDatabase 数据库长期存储在计算机内、有组织、可共享的大量数据的集合
DBMSDatabase Management System 数据库管理系统专门用于建立、使用和维护数据库的系统软件（如 MySQL、Oracle、SQL Server）
DBSDatabase System 数据库系统由 DB、DBMS、应用程序、数据库管理员（DBA）和用户等构成的整个人机系统
DBADatabase Administrator 管理员负责数据库设计、维护、安全性与完整性控制的人员
📝 考纲·题型举例（单选）原题：DB、DBS、DBMS 的关系是？——答案 DBS 包括 DBMS 和 DB。记忆法：DBS（系统）＞ DBMS（软件）＞ DB（数据），DB 是被 DBMS 管理的那堆数据。
DBMS 的主要功能（简答模板）：
①数据定义功能（DDL 建模式/表）；
②数据操纵功能（DML 增删改查）；
③数据控制功能（并发控制、安全性、完整性、故障恢复）；
④数据库建立维护功能（加载、转储、重组、重构）。

二、数据管理技术的发展（领会）

领会 数据管理技术的发展阶段与区别。
阶段数据管理者特点
人工管理阶段程序自己数据不保存、不共享；数据和程序不具有独立性
文件系统阶段操作系统数据可长期保存；数据共享性差，冗余度大；数据独立性差；由文件系统对数据进行管理
数据库系统阶段DBMS数据结构化；数据共享度高，冗余度小；数据独立性高；由 DBMS 对数据进行管理（安全性/完整性/并发/恢复）
数据独立性是数据库阶段最本质的优点：物理独立性（存储结构变了，程序和逻辑结构不受影响）＋ 逻辑独立性（逻辑结构变了，程序不受影响）。第六节的"两级映像"就是实现它的机制，两处要连着记。

三、数据模型：概念、三要素、分类 ⭐

识记 数据模型的概念、分类、组成要素。
数据模型：对数据库结构与行为的抽象描述，是 DBMS 实现的基础，用来描述静态特征（数据结构）、动态特征（数据操作）和约束条件。
组成三要素（必背，常考单选/简答）：
① 数据结构——描述对象的类型与联系（静态特征）；
② 数据操作——查询、插入、删除、修改等操作与规则（动态特征）；
③ 数据的完整性约束条件——制约数据间关系与语义的规则。
分类（按层次分两类）：
  • 概念模型（信息模型）：面向用户与业务，如 E-R 模型。
  • 逻辑模型（结构模型）：面向 DBMS，按数据结构命名 → 层次模型、网状模型、关系模型；此外还有非传统模型（面向对象、对象关系、半结构化/XML）。
  • 物理模型：面向计算机操作系统。
⚠️ 易混：问"数据模型的三要素"答结构 / 操作 / 完整性约束；问"数据模型的分类"答概念模型与逻辑模型（或层次/网状/关系）。别把两套答案串了。

四、概念模型与 E-R 图 ⭐ 难点

领会 实体间联系、实体-联系方法；简单应用 根据有关信息设计 E-R 图。
术语含义图形记号
实体客观存在并可相互区分的事物（一个学生、一门课）矩形
属性实体具有的特性（学号、姓名、年龄）椭圆，连到实体
码（键）能唯一标识一个实体的属性或属性组（学号）属性名下画直线
实体集同一类实体的集合矩形
联系实体集之间或实体内部的对应关系菱形，标 1、n 或 m
域一组同质值的集合（年龄取值 0～150）—
实体间的联系：分两类——同一实体集内、不同实体集间；四种类型：
类型记法典型例子
一对一1 : 1学生 ↔ 借书证；班长 ↔ 班级
一对多1 : n班级 → 学生；科室 → 医生
多对多m : n学生 ↔ 课程；病人 ↔ 药品
自身联系1 : n 或 m : n职工与其直接上级（同一实体集内）
画法三查：①实体用矩形、属性用椭圆、联系用菱形；②联系旁标 1 / n / m；③联系自身的属性（如"选修"的"成绩"）挂在菱形上——E-R 转关系模式时它会被并进联系生成的那张表。
  1. 找实体：把题干里的名词分成"独立实体"与"属性"。能再细分出多个特征、需要单独管理的做成实体，否则当属性。
  2. 定属性与码：给每个实体列属性，圈出能唯一标识的码。
  3. 判联系类型：逐对实体双向问"一个 A 对应几个 B / 一个 B 对应几个 A"，取乘积 → 1:1、1:n 还是 m:n。
  4. 挂联系属性：只有属于"关系本身"的信息（成绩、借书日期）才画到菱形上。
⚠️ 常见扣分：把"班主任"当成一个实体（应是"班级—教师"的 1:1 联系），或把 m:n 联系漏画成 1:n，导致后面第 10 章转换时少生成一张表。

五、三种逻辑模型（领会）

领会 层次模型、网状模型、关系模型。
模型数据结构特点代表
层次模型树形结构有且只有一个根结点，其余结点有且只有一个双亲；简单直观，但表示多对多困难、查询必须走路径IMS
网状模型图（有向图）允许一个以上结点无双亲、一个结点可有多个双亲；更灵活，但结构复杂、编程麻烦IDMS、CODASYL
关系模型二维表以关系数学为基础，数据结构简单、独立性高，用户只需声明"要什么"而不必写"怎么取"；但有集合操作开销、效率相对较低MySQL、Oracle
非关系模型对比小结：三者都用数据结构命名；关系模型是目前应用最广、也是本课程后半程（第 2～9 章）的理论基础。

六、三级模式、两级映像与数据独立性 ⭐

识记 数据库系统的三级模式结构；领会 二级映像与数据独立性。
级别别名描述对象个数
模式（逻辑模式）全体数据的公共视图，描述数据的逻辑结构数据库中全部数据只有 1 个
外模式（子模式 / 用户模式）某个用户看得见、用得到的局部数据的逻辑结构，通常是基本表的子集（视图）局部数据可以有多个
内模式（存储模式）数据物理存储结构与存取方法（索引、聚簇、文件组织）全局物理层只有 1 个
两级映像：
映像连接保证了哪种独立性
外模式 / 模式映像外模式 ↔ 模式逻辑独立性——模式变了，改这份映像，外模式和应用程序不必变
模式 / 内模式映像模式 ↔ 内模式物理独立性——存储方式变了，改这份映像，模式与程序不必变
🔑 记忆："三级"从下往上是 内模式（物理）→ 模式（全局逻辑）→ 外模式（用户局部）；映像夹在两层之间，谁被改动就改它下面那条映像。选择题常问"保证逻辑独立性的是哪条映像"→ 外模式/模式映像。

七、大数据简介（识记 / 领会）

识记 大数据的基本概念；领会 大数据的处理过程、数据管理技术的发展。
大数据（Big Data）：海量数据需要以新的计算模式为手段，获取、存储、管理、处理并提炼数据以帮助使用者决策。
特征（4V+1C，教材口径，常考多选/简答）：Volume 数据量巨大、Variety 数据类型繁多（结构化/半结构化/非结构化）、Value 价值——需对海量数据进行挖掘才能产生重大价值（价值密度低只是挖掘难度的背景理解）、Velocity 处理速度快、Complexity 数据复杂、处理技术复杂。
大数据的处理过程：数据的采集和预处理、大数据分析、数据可视化。
NoSQL 类型存储形式代表
键值 Key-Value按 key 哈希存取Redis、DynamoDB
列存储（列族）按列簇组织、便于横向扩展HBase、Cassandra
文档型JSON/XML 半结构化文档MongoDB、CouchDB
图形点 + 边，擅长关系网络Neo4j
与传统数据库的关系（领会）：大数据不是取代 DBMS，而是在数据管理技术上从"关系数据库"扩展到"分布式 + 非关系 + 云"；SQL 与 NoSQL 常混合使用（SQL 管核心业务、NoSQL 管海量灵活数据）。
⚠️ 易错：① 多选若选项出现 Veracity（真实性），按教材 4V+1C 它不属于大数据特征（那是业界扩展版 5V 的说法）；② Value 按教材答“需对大量数据进行处理、挖掘其潜在价值”，“价值密度低”可作补充说明，别只写“价值高”。

八、本章速记小结

三概念大小：DBS ＞ DBMS ＞ DB（DBS 还含 DBA、用户、应用程序）。
三阶段：人工管理 → 文件系统 → 数据库系统，进步的核心是数据独立性与结构化、共享、低冗余。
三要素：数据结构 + 数据操作 + 完整性约束。
三逻辑模型：层次（树）、网状（图）、关系（二维表）。
三级模式两映像：外模式（多个，局部）→ 模式（1 个，全局逻辑）→ 内模式（1 个，物理）；外/模映像 → 逻辑独立性，模/内映像 → 物理独立性。
E-R 图三形状：矩形=实体、椭圆=属性、菱形=联系；联系类型 1:1 / 1:n / m:n，联系上可挂自己的属性。
大数据 4V+1C（教材口径）：Volume、Variety、Value（挖掘才产生价值）、Velocity、Complexity（复杂性）；Veracity 真实性不属教材特征。
