一、单项选择题（15 小题，共 30 分）

第1题点击展开答案
数据管理技术发展历程中,具有数据不保存、不共享特点的是
A. 人工管理阶段B. 文件系统阶段C. 数据库系统阶段D. 操作系统阶段
答案：A
解析：数据管理三阶段中，人工管理阶段（20世纪50年代以前）数据随程序而生、随程序而灭，不保存、程序之间不共享、每组数据对应一个程序；文件系统阶段数据可长期保存但共享性差、冗余度大；数据库系统阶段高共享、低冗余、独立性好。D 是干扰项（操作系统不是数据管理的一个阶段）。故选 A。
考点：数据管理技术的发展
第2题点击展开答案
数据库系统的三级模式结构中,位于最外层,又称为子模式或用户模式的是
A. 模式B. 外模式C. 设计模式D. 内模式
答案：B
解析：三级模式由外到内：外模式（最外层，用户可见的局部数据逻辑结构，又称子模式/用户模式）→ 模式（全体数据的逻辑结构，即数据库本身）→ 内模式（物理存储结构，又称存储模式）。C 为干扰项。故选 B。
考点：三级模式两级映像
第3题点击展开答案
关系模式中的一个主码
A. 只能由一个属性组成B. 至少由一个属性组成C. 必须由多个属性组成D. 必须由关系模式的所有属性组成
答案：B
解析：主码（主键）是能唯一标识元组的属性或属性组：可以由单个属性组成（如学号），也可以由多个属性共同组成（如选修表的（学号,课程编号)）。"只能一个"（A）与"必须多个"（C）都太绝对，D 混淆了"全码"概念。故"至少由一个属性组成"最准确，选 B。
考点：关系的形式化定义与码
第4题点击展开答案
关系模型上的关系操作语言包括
A. 关系代数语言、集合运算语言和关系演算语言B. 关系代数语言、集合运算语言和结构化查询语言C. 结构化查询语言、集合运算语言和关系演算语言D. 关系代数语言、关系演算语言和结构化查询语言
答案：A
解析：按教材分类，关系模型上的关系操作语言包括三类：关系代数语言、集合运算语言、关系演算语言（前两者基于运算，后者基于谓词演算）。SQL（结构化查询语言）是语言的实际实现标准，不属于这一形式化分类，含"结构化查询语言"的 B/C/D 均排除。故选 A。
考点：关系操作及其特点
第5题点击展开答案
关系数据库的约束规则中,关系的主码属性不能取空值。
A. 实体完整性B. 参照完整性C. 用户定义完整性D. 外码完整性
答案：A
解析：实体完整性规则：若属性（或属性组）K 是基本关系的主码，则 K 中的每个属性都不能取空值（主码是实体的唯一标识，为空就无法区分元组）。参照完整性约束的是外码与另一关系主码的对应关系；用户定义完整性是针对具体应用的条件约束；"外码完整性"不是标准名称（即参照完整性）。故选 A。
考点：关系的三类完整性规则
第6题点击展开答案
在MySQL中,使字段的输入值大于0的约束是
A. CHECKB. PRIMARY KEYC. UNIQUE KEYD. FOREIGN KEY
答案：A
解析："输入值大于 0"是列取值的条件约束，属于用户定义完整性，用 CHECK(分数>0) 实现。PRIMARY KEY 保证唯一+非空（实体完整性），UNIQUE KEY 只保证不重复，FOREIGN KEY 实现表间参照（参照完整性），三者都管不了"大于 0"这种取值范围。故选 A。
考点：CHECK 与非空约束
第7题点击展开答案
在MySQL数据库中,修改数据库的SQL命令是
A. ALTER DATABASEB. DELETE DATABASEC. INSERT DATABASED. UPDATE DATABASE
答案：A
解析：MySQL 定义数据库四条语句：CREATE DATABASE（创建）、ALTER DATABASE（修改，常改字符集/排序规则）、DROP DATABASE（删除）、SHOW DATABASES（查看）。删除数据库用 DROP 而非 DELETE；INSERT/UPDATE 是操作数据的 DML，不能作用于数据库。故选 A。
考点：定义数据库四条语句
第8题点击展开答案
在MySQL中,用于删除数据表数据的命令是
A. UPDATEB. DELETEC. INSERTD. FIND
答案：B
解析：删除表中数据（行）用 DELETE FROM 表 [WHERE 条件]（另有 TRUNCATE TABLE 一次性清空）。UPDATE 修改、INSERT 插入；MySQL 根本没有 FIND 命令（查询用 SELECT）。注意与删除表本身的 DROP TABLE 区分。故选 B。
考点：DELETE 与 TRUNCATE
第9题点击展开答案
在MySQL查询中,如果WHERE子句为:姓名LIKE%民,下列姓名不会被查询出来的是
A. 民子B. 全民C. 大民子D. 民民民
答案：A
解析：通配符 % 匹配任意长度（含 0 长度）字符串，'%民' 的语义是以“民”结尾。逐字符核验四个姓名：A“民子”结尾是“子”→不匹配；B“全民”结尾是“民”→匹配；C“大民子”结尾是“子”→不匹配；D“民民民”结尾是“民”→匹配。
⚠️ 存疑标注：按上述规则题面会出现 A、C 两个“不会被查询出来”的选项，疑为原卷模式实为 '民%'（以民开头，则不匹配的是 B、C）或截图个别字符失真——截图清晰度有限，本题为争议题。流传参考答案取 A，按“单选题选最先命中项”暂记 A，复习时重点掌握 % 与 _ 通配符本身。
考点：WHERE 的七类条件（LIKE）
第10题点击展开答案
在MySQL中,LIMIT1,3描述的是
A. 获取第1条到第3条记录B. 获取第1条到第4条记录C. 获取第2条到第4条记录D. 获取第2条到第5条记录
答案：C
解析：LIMIT 偏移量, 行数：偏移量从 0 开始计。LIMIT 1,3 = 跳过第 1 条，从第 2 条开始取 3 条，即第 2、3、4 条记录。故选 C。
考点：排序与限制行数（LIMIT）
第11题点击展开答案
在关系表:学校(编号,校名,分数线)中,编号是主键,要查询所有分数线不是最高的学校的编号,不正确的MySQL查询语句是
A. SELECT编号FROM学校WHERE分数线<(SELECT MAX(分数线)FROM 学校);B. SELECT S2.编号FROM学校S1,学校S2 WHERE S1.分数线<S2.分数线;C. SELECT编号FROM学校S1 WHERE EXISTS (SELECT*FROM学校S2 WHERE (S1.分数线<S2.分数线));D. SELECT编号FROM学校WHERE分数线<SOME(SELECT分数线FROM学校);
答案：B
解析：逐项验证语义"分数线 < 最高分数线"：
A：标量子查询取 MAX(分数线) 再比较，✔ 正确。
C：相关子查询 EXISTS——"存在另一所学校分数线比我校高" ⇔ 本校不是最高，✔ 正确。
D：< SOME(子查询)（SOME=ANY，小于集合中某一个值）⇔ 小于最大值，✔ 正确。
B：自身连接写法失真且方向反了——FROM 学校 S1, 学校 S2 与 WHERE S1.分数线<S2.分数线 都用了 S1 别名，但 SELECT 侧只出现 S2；更关键的是即便按 SELECT S2.编号 FROM 学校 S1, 学校 S2 WHERE S1.分数线<S2.分数线 的“补全”理解，S2 行取的是分数线更高那所的编号，恰好把“不是最高”的学校查漏/查反，语义错误。故选 B。
考点：子查询 IN/比较/EXISTS另见：连接查询
第12题点击展开答案
在MySQL中,下列关于视图的描述不正确的是
A. 基表中的数据发生变化,从视图中查询出的数据也随之改变B. 视图也叫虚表,是从一个或几个基本表(或视图)导出的表C. 视图只存储视图的定义,不存放视图对应的数据D. 视图中总是存储数据
答案：D
解析：视图是虚表：数据库中只存视图定义（B、C 正确），不存放视图对应的数据，数据仍来自基表，基表变化时视图查询结果随之变化（A 正确）。D"视图中总是存储数据"与"虚表、只存定义"直接矛盾（只有物化视图才存数据，MySQL 默认视图不物化），是错误的描述。故选 D。
考点：视图的含义与优点
第13题点击展开答案
需要使用关键字UNIQUE创建的索引是
A. 唯一性索引B. 主键C. 空值索引D. 聚簇索引
答案：A
解析：CREATE UNIQUE INDEX / 建表时 UNIQUE KEY 创建的就是唯一性索引（列值不许重复，允许空值）。主键约束虽然底层也是唯一+非空索引，但定义它用 PRIMARY KEY 关键字、无须 UNIQUE；聚簇索引由 PRIMARY KEY（InnoDB 默认）等产生；"空值索引"不存在。故选 A。
考点：索引操作（三建两删一看）另见：主键与唯一性约束
第14题点击展开答案
在MySQL中,存储了用户对某个数据库的操作权限的表是
A. Columns_privB. dbC. procs_privD. tables_priv
答案：B
解析：mysql 库六张权限表各管一级：user（全局级）、db（库级——用户对某个数据库的操作权限）、tables_priv（表级）、columns_priv（列级）、procs_priv（存储过程/函数级）、proxies_priv（代理用户）。题干"对某个数据库"→ db 表。故选 B。
考点：权限表所在库与包含的表
第15题点击展开答案
下列范式中,限制了主属性对码的依赖关系的是
A. 1NFB. 2NFC. 3NFD. BCNF
答案：D
解析：逐级看消除的依赖：2NF 消除非主属性对码的部分依赖；3NF 消除非主属性对码的传递依赖——两者都只管非主属性，主属性对码的部分/传递依赖没被限制。BCNF 要求每个非平凡的函数依赖的决定域都必含码，等价于消除主属性对码的部分和传递依赖（连主属性也被约束）。故选 D。
考点：码与五级范式

二、简答题（6 小题，共 30 分）

第16题点击展开答案
简述在数据库技术中,数据模型按应用层次可分成的三类模型。
参考答案
要点：①数据模型按应用层次可分为概念模型、逻辑模型、物理模型三类。
②概念模型：面向数据库用户的现实世界的模型，按用户的观点对数据和信息建模，是对现实世界的第一层抽象，又称信息模型（典型表示：E-R 图）。
③逻辑模型：直接面向数据库的逻辑结构，按计算机的观点对数据建模，是对现实世界的第二层抽象，是概念模型的数据化，是事务以及事务之间联系的数据描述，并提供了表示和组织数据的方法，是具体的 DBMS 所支持的数据模型（如关系模型）。
④物理模型：面向计算机物理表示的模型，面向计算机系统，是对数据最底层的抽象，描述数据在储存介质的组织结构，既与具体 DBMS 有关，也与操作系统和硬件有关，如存取路径、存储方式、索引等，由 DBMS 具体实现。
考点：数据模型概念与分类
第17题点击展开答案
简述关系代数运算的三要素及关系代数中的操作。
参考答案
要点：①三要素：运算符、运算对象、运算结果。
②关系代数中的操作分为以下两类：
传统的集合运算：并、交、差、笛卡儿积。
专门的关系运算：如选择、投影、连接、除。
考点：关系代数运算三要素与分类

三、综合题 / 设计题（4 小题，共 40 分）

第22题点击展开答案
某工厂的计算机管理中只需要保存如下信息：
需要保存的信息
实体属性
车间车间名称、车间主任
产品产品编号、产品名、成本价
电商电商名、负责人
其中（约束条件）
  1. 一个车间可生产多种产品，每种产品只能在一个车间生产；
  2. 一种产品可在多个电商售卖，一个电商可售卖多种产品；
  3. 车间的车间名称是唯一的，产品的产品编号是唯一的，电商的电商名是唯一的。
要求
  1. 画出符合上述要求的全局 E-R 图（不必画实体的属性）6 分
  2. 将 E-R 图转换成一组符合 3NF 规范的关系模式，并指出每个关系模式的主码和外码6 分
  3. 用 MySQL 命令建立“车间”表，要包含主码约束，各属性的数据类型自行定义4 分
参考答案
(1) 全局 E-R 图：
矩形＝实体，菱形＝联系，连线旁的 1 / n / m ＝联系的基数；题目要求不必画属性，故不画椭圆
车间—产品：1 : n（一个车间生产多种产品，每种产品只能在一个车间生产）；产品—电商：m : n（一种产品可在多个电商售卖，一个电商可售卖多种产品）。
评分参考：1:n 联系（生产）画正确得 3 分；m:n 联系（售卖）画正确得 3 分——矩形＝实体、菱形＝联系、连线旁标注 1/n/m，三样缺一扣分。
(2) 转换为 3NF 关系模式：①车间（车间名称，车间主任）——主码：车间名称；无外码。
②产品（产品编号，产品名，成本价，车间名称）——主码：产品编号；外码：车间名称（参照"车间"的车间名称，1:n 联系把"一"端主码并入"多"端）。
③电商（电商名，负责人）——主码：电商名；无外码。
④售卖（电商名，产品编号）——主码：(电商名, 产品编号) 组合；外码：电商名（参照"电商"）、产品编号（参照"产品"）（m:n 联系单独成一个关系）。
四个关系均无非主属性对码的部分/传递依赖，符合 3NF。
(3) 建立"车间"表：
CREATE TABLE 车间 (
    车间名称 VARCHAR(20) PRIMARY KEY,
    车间主任 VARCHAR(10)
);
要点：主码约束 PRIMARY KEY 必须写出；数据类型自行定义、合理即可（中文表名列名 MySQL 允许，实际项目建议用 workshop 等英文名）。

关系 R
ABC
p2c
p3a
q3d
关系 S
CD
ax
cy
cz
要求
  1. ΠC(R) ∪ ΠC(S) = ?4 分
  2. σB=2(R ⋈ S) = ?4 分
参考答案
(1) 中间步骤：ΠC(R)：取 R 的 C 列并去重 = {(a), (c), (d)}；ΠC(S) = {(a), (c)}。

(2) 中间步骤：先算选择 σB=2(R) = {(p, 2, c)}（仅第一行 B=2）；再与 S 做自然连接：公共属性为 C，该行 C=c，S 中 C=c 的元组有 (c,y)、(c,z) 两条。

第24题点击展开答案
某学生-课程管理数据库中包含学生表、课程表和选修表。三个表的表结构分别如题23表(a)至题23表(c)所示。
表(a) 学生表
字段类型约束
学号varchar(6)主键
姓名varchar(10)—
性别char(2)—
年龄int—
表(b) 课程表
字段类型约束
课程编号varchar(6)主键
课程名称varchar(40)—
系名varchar(40)—
学分tinyint—
表(c) 选修表
字段类型约束
学号varchar(6)主键
课程编号varchar(6)主键
成绩int—
使用 MySQL 命令完成下列操作
  1. 查询平均成绩在 60 分及 60 分以上的课程的课程编号和平均成绩2 分
  2. 查找选修了课程名称为“数据结构”的所有学生的姓名和年龄2 分
  3. 修改学号为“202345”学生的年龄，年龄改为 19 岁2 分
  4. 创建一个视图“V1”，该视图能够查询每门课程的课程编号和最高成绩2 分
参考答案
(1) 分组+HAVING：
SELECT 课程编号, AVG(成绩) AS 平均成绩
FROM 选修表
GROUP BY 课程编号
HAVING AVG(成绩) >= 60;
要点：聚合条件必须放 HAVING（WHERE 里不能写聚合函数），"60 分及以上"用 >=。
(2) 三表连接（或子查询）：
SELECT s.姓名, s.年龄
FROM 学生表 s
JOIN 选修表 x ON s.学号 = x.学号
JOIN 课程表 c ON c.课程编号 = x.课程编号
WHERE c.课程名称 = '数据结构';
等价写法：学号 IN (子查询查"数据结构"的选修学号)。
(3) UPDATE：
UPDATE 学生表 SET 年龄 = 19 WHERE 学号 = '202345';
要点：学号是 varchar，值要加引号；WHERE 不能漏。
(4) 创建视图：
CREATE VIEW V1 AS
SELECT 课程编号, MAX(成绩) AS 最高成绩
FROM 选修表
GROUP BY 课程编号;
要点：CREATE VIEW 视图名 AS 子查询，每门课程一行用 GROUP BY 分组取 MAX。
考点：分组查询与聚合函数考点：连接查询考点：UPDATE考点：视图操作
第25题点击展开答案
给定关系模式 R<U,F>，其中属性全集 U={A,B,C,D,E,G}，函数依赖集 F={A→CD, B→E, AB→G}
要求
  1. 请计算属性集 AB 的属性集闭包 (AB)+F3 分
  2. 该关系模式是否属于第三范式？为什么？5 分
参考答案
(1) 求 (AB)+：X⁺ 求闭包三步：初值 X⁺=AB；用 A→CD 得 ABCD；用 B→E 得 ABCDE；用 AB→G 得 ABCDEG = U。
∴ (AB)⁺F = ABCDEG。（AB 能推出全部属性，且其任何真子集 A⁺=ACD、B⁺=BE 都≠U，故 AB 是唯一候选码，A、B 均为主属性，C、D、E、G 为非主属性。）
(2) 不属于 3NF。理由：3NF 要求每一个非平凡函数依赖 X→Y，要么 X 必含码，要么 Y 属于某个候选码（主属性）。考察依赖 B→E：B⁺=BE≠U，B 不是超码（B 单独只是候选码 AB 的一部分）；而右端属性 E 是非主属性、不属于任何候选码。即存在非主属性 E 对候选码 AB 的传递依赖（AB→B→E，且 B↛AB），违反 3NF。∴ R 不属于第三范式。（评分参考：结论 2 分，原因 3 分。）
考点：Armstrong 公理与属性集闭包考点：范式判定 3NF考点：完全/部分/传递依赖
