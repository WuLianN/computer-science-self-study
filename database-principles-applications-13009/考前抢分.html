三、🔴 简答 6 题（30 分）——关键词背到能默写

本卷原题即最可能重考的问法；同一知识点换个问法概率极高。每题记"骨架词"，考试扩写成句。

16数据模型三类（按应用层次）

骨架：① 概念模型——面向用户、现实世界第一层抽象、E-R 图表示；② 逻辑模型——面向 DBMS、第二层抽象、概念模型数据化（如关系模型）；③ 物理模型——面向计算机、最底层抽象、描述存取路径/存储方式/索引。
▶ 去概论页背

17关系代数三要素及操作

骨架：三要素 = 运算符、运算对象、运算结果。操作分两类：① 传统集合运算——并、交、差、笛卡儿积；② 专门关系运算——选择、投影、连接、除。
▶ 去关系模型页背

18定义外键应遵守的规则

骨架（任答 5 点）：①被参照表须已建或正在建；②被参照表须定义主键或唯一约束；③REFERENCES 后列名须是对方主键/唯一列；④主键不能空、外键可空；⑤外键与主键列数相同；⑥外键与主键数据类型相同。
▶ 去完整性页背

19索引的概念与作用

骨架：概念 = 按一列/多列排序、建立指向记录位置的指针。作用（任答 3 点）：①提高查询速度；②保证列值唯一性；③查询优化靠索引；④提高 ORDER BY / GROUP BY 执行速度。
▶ 去视图索引页背

20GRANT 授权（题写型）

骨架：GRANT SELECT, DELETE ON salesDB.`order` TO 'song'@'localhost' WITH GRANT OPTION; 关键：库名.表名定位对象级权限、WITH GRANT OPTION 允许再授权（漏写得一半分）、order 是保留字要反引号。
▶ 去权限页背

21需求分析任务与方法

骨架：任务 = 对处理对象详细调查、收集支持系统目标的基础数据及其处理方法。方法 = 结构化分析，自顶向下、逐层分解，用数据流图 DFD + 数据字典 DD 描述系统。
▶ 去设计页背

四、🧮 综合题两大推导套路（Q23 关系代数 · Q25 规范化）

23关系代数：先内后外写中间步骤

投影 Π 会去重：ΠC(R) 取 C 列并去掉重复元组。
自然连接 ⋈：按公共属性等值匹配、公共列只保留一次。
本卷 (2) σB=2(R⋈S)：先 σB=2(R)={(p,2,c)}，其 C=c 与 S 中 C=c 的 (c,y)(c,z) 连接 → {(p,2,c,y),(p,2,c,z)}。
口诀：括号里先算、结果写成元组集合、标清属性列。
▶ 自然连接 ▶ 八种运算

25规范化：求闭包 + 判 3NF

求 (AB)⁺ 三步：初值 AB → 反复用 F 中依赖把右端并入，直到不再增长。本卷 A→CD、B→E、AB→G 依次并入得 ABCDEG=U，故 AB 是唯一候选码。
判 3NF：看有无非主属性对码的传递依赖。B→E 中 B 非超码、E 非主属性 ⇒ AB→B→E 传递依赖 ⇒ 不属 3NF。
结论 2 分、原因 3 分，务必写出"哪个依赖、违反哪条"。
▶ 属性闭包 ▶ 五级范式

22E-R 图 → 3NF 关系模式 → CREATE TABLE

转换口诀：1:n 联系把"一"端主码并入"多"端作外码（本题车间→产品，产品加"车间名称"外码）；m:n 联系单独成一个关系（售卖(电商名,产品编号)，组合主码）。每个模式标出主码＋外码。建表：CREATE TABLE 车间(车间名称 VARCHAR(20) PRIMARY KEY, 车间主任 VARCHAR(10));——主码约束 PRIMARY KEY 必须写。
▶ E-R 转关系模式 ▶ CREATE TABLE

五、📌 SQL 写作六大模板（覆盖 Q24 全部小问）

设计题按步骤给分——把框架写出来就有大半分。每模板背"加粗行"即可，中文表名列名 MySQL 允许。

1分组聚合 + HAVING（Q24-1 平均成绩≥60）

SELECT 课程编号, AVG(成绩) AS 平均成绩
FROM 选修表
GROUP BY 课程编号
HAVING AVG(成绩) >= 60;   ← 聚合条件只能放 HAVING，不能放 WHERE
三句口诀：先 WHERE 过滤行 → GROUP BY 分组 → HAVING 过滤组；SELECT 里可放 AVG/MAX/COUNT 等聚合函数。

2多表连接 JOIN（Q24-2 选修"数据结构"的学生）

SELECT s.姓名, s.年龄
FROM 学生表 s
JOIN 选修表 x ON s.学号 = x.学号
JOIN 课程表 c ON c.课程编号 = x.课程编号
WHERE c.课程名称 = '数据结构';
等价写法：学号 IN (子查询查"数据结构"的选修学号)。跨表取数就 JOIN...ON...，一个表一个别名。

3UPDATE 改数据（Q24-3 改年龄）

UPDATE 学生表 SET 年龄 = 19 WHERE 学号 = '202345';
⚠️ 两个丢分点：学号是 varchar，值要加引号 '202345'；WHERE 绝不能漏（漏了改全表）。

4CREATE VIEW 建视图（Q24-4 每门课最高分）

CREATE VIEW V1 AS
SELECT 课程编号, MAX(成绩) AS 最高成绩
FROM 选修表
GROUP BY 课程编号;
骨架 = CREATE VIEW 视图名 AS 子查询；"每门课程一行"靠 GROUP BY 分组取 MAX。

5CREATE TABLE 建表（Q22-3 含主码约束）

CREATE TABLE 车间 (
    车间名称 VARCHAR(20) PRIMARY KEY,
    车间主任 VARCHAR(10)
);
主码 PRIMARY KEY 必须写；数据类型自定合理即可（varchar 要带长度）。

6GRANT 授权（简答 20 同款）

GRANT SELECT, DELETE ON salesDB.`order`
TO 'song'@'localhost' WITH GRANT OPTION;
WITH GRANT OPTION＝允许再授权；`order` 反引号绕开保留字；用户须已存在故不写 IDENTIFIED BY。

六、🟡 选择题 30 分：只抢"背概念就对"的那批

15 题里绝大多数是纯概念辨析，背过＝白捡。下面按考点列送分点与陷阱。

🎁 背了就能拿

数据不保存不共享＝人工管理阶段（1）· 最外层/子模式/用户模式＝外模式（2）· 主码至少一个属性（3）· 关系操作语言＝关系代数+集合运算+关系演算，不含 SQL（4）· 主码非空＝实体完整性（5）· 值>0 用 CHECK（6）· 修改数据库＝ALTER DATABASE（7）· 删数据＝DELETE（8）· LIMIT 1,3＝第2~4条（偏移从0计，10）· 视图是虚表只存定义（12）· UNIQUE 建唯一性索引（13）· 存库级权限＝db 表（14）· 限制主属性对码依赖＝BCNF（15）。

⚡ 陷阱 / 争议题预防针

① LIKE '%民'＝以"民"结尾，"全民/民民民"能查出、"民子"查不出——本卷第 9 题截图存疑、流传答案取 A，考场按"% 结尾"直觉选，别较真；② 第 11 题"查找不是最高"选写法错的那句（自身连接 SELECT 只出现 S2、方向反）＝B；③ 删除表本身用 DROP TABLE、删数据用 DELETE，别混；④ 主键≠外码完整性（无此标准名）。
📌 本卷无官方答案，选择题答案依考纲与教材逐题推定复核（第 9 题已标注争议）。完整逐题详解见 2026.1 真题详解，底部有答案速查表。

七、🎯 考场策略与时间分配（150 分钟）

  • 答题顺序：简答（35'，背出来写得飞快，先锁 30 分）→ 综合/设计（70'，套 SQL 模板 + 规范化推导）→ 选择（30'，15 题别超 30 分钟）→ 检查（15'，回头补空着的 WHERE/引号）。
  • 大题绝不留白：SQL 写不出完整句就把 SELECT…FROM…WHERE 框架、GROUP BY、CREATE VIEW…AS 写上；关系代数先写中间步骤再写结果，按步给分。
  • HAVING vs WHERE 是 SQL 第一大扣分点：凡"聚合函数的条件"（平均≥60、最高分）一律进 HAVING。
  • varchar 值加引号、UPDATE/DELETE 带 WHERE：学号 '202345' 是字符串要加引号，漏 WHERE 直接判错。
  • 规范化题写清"哪个依赖、违反哪条"：求闭包逐步并入、判 3NF 点明传递依赖，别只写结论。
  • 目标管理：综合 30 + 简答 20 + 选择 16 ≈ 66，60 线外还有容错——哪题翻车都不影响及格。
