一、网络安全协议：概念、特点与功能分类 ⭐

识记 网络安全协议的概念、特点和基于功能的分类。
概念：网络安全协议就是在协议中采用了若干密码算法——运用加密技术、认证技术，以保证信息安全交换的网络协议。（名词解释按此写：协议 + 密码算法 + 安全交换。）
安全协议具有以下三种特点：保密性、完整性、认证性。
按照其完成的功能分类（五类，必背）：
#类别要解决的问题典型代表
1密钥建立协议在不安全信道上安全地协商出会话密钥Diffie-Hellman 密钥交换
2认证协议确认对方身份是否合法（实体认证、消息认证）Kerberos、挑战—应答
3认证和密钥交换协议既认证身份又交换密钥（实际系统最常用）IKE、SSL/TLS 握手
4电子商务协议面向交易：公平性、不可抵赖、支付信息保护SET
5安全通信协议保护通信过程中数据的机密与完整IPSec、SSL/TLS、SSH、S/MIME
🔑 记忆主线：功能分类是从"先建密钥 → 再认证 → 二者合一 → 保护通信 → 保护交易"逐层升级的，层次越靠后涉及的安全目标越多（交易类还要加不可否认与公平性）。

二、TCP/IP 协议的不安全因素（领会）

领会 TCP/IP 协议的不安全因素。
  1. 利用系统漏洞与其他个体通信，窃取信息；
  2. 窃取网络上的通信内容，对他人的隐私构成威胁；
  3. 某一资源被他人非法使用；
  4. 对正在传输的数据进行恶意修改，造成接收者的误解；
  5. 为了获得非法的特权，攻击者会发掘系统漏洞并侵入系统内部。
🔑 根源在于 TCP/IP 设计之初以互通与效率为目标、缺乏内置的安全机制：地址可伪造、多数协议明文传输、无强制认证。正因如此，安全只能"分层外挂"——于是有了 IPSec（网络层）、SSL/TLS（传输层）、SSH/SET/S-MIME（应用层），这就是下一节的线索。

三、各网络层下的经典安全协议 ⭐⭐

识记 各个网络层下的经典安全协议（考试常给协议名让你归层，或给层次让你列协议）。
越往下越通用、透明（一次部署保护所有上层应用）；越往上越贴近业务（能做交易级安全如不可否认、支付信息隔离）
层次协议括号内是它的定位（考试按此归层）
网络层IPSec网络层安全协议，保护 IP 包，VPN 的核心
传输层SSL / TLS传输层安全协议，为应用提供加密通道
应用层SET信用卡支付安全协议（电子交易，多方认证 + 双重签名）
S-HTTPWeb 安全协议（保护单条 HTTP 请求／响应报文）
PGP电子邮件安全协议（"pretty good privacy"，混合加密 + 信任网）
S/MIME电子邮件安全协议（MIME 报文的安全扩展，数字签名与邮件加密）
PEM电子邮件安全协议（隐私增强邮件，Internet 标准一类的邮件加密方案）
SSH远程登录安全协议（安全外壳，替代 telnet／rlogin／ftp）
Kerberos网络验证协议（基于可信第三方与票据的认证系统）
🔑 口诀"网 IPSec、传 SSL、应用一堆（SET·S-HTTP·PGP·S/MIME·PEM·SSH·Kerberos）"。爱考区分：S-HTTP 保护单条 Web 报文，SSL 保护整条通信通道；SET 是交易协议、SSL 是通道协议。

四、网络层安全协议 IPSec ⭐⭐

识记 IPSec 协议的组成和体系结构；领会 IPSec 的功能和工作原理，如何用于加密／认证／数据完整性保护，SA 的概念和两种工作模式。
IPSec 协议由 4 个主要部分组成：
组成全称职责
ESP封装安全载荷协议（Encapsulating Security Payload）同时提供数据完整性验证和数据加密传输机制（ confidentiality + 完整性）
AH验证头协议（Authentication Header）只提供数据完整性验证机制：证明数据源端点、保证完整性、防止数据篡改和重播（不加密载荷）
SA安全关联（Security Association）通信双方为本次安全服务协商一致的"合同"（用哪个协议、哪种算法、什么密钥、模式）
IKE互联网密钥交换协议（Internet Key Exchange）自动协商与管理 SA、协商并分发票据密钥（兼具认证与密钥交换协议特征）
功能与工作原理（领会）：IPSec 是通过端对端的安全性来提供主动的保护，以防止专用网络与 Internet 的攻击，是安全联网的长期方向。它提供了两种安全协议：验证头 AH 与封装安全有效载荷 ESP，这两种协议以 IP 扩展头的方式被增加到 IP 包中，可以对IP 数据包或上层协议数据包进行安全保护，提高了对 IP 数据项的安全性。
🔑 三个安全目标怎么落地（考纲要点）：加密 → ESP；认证（源端点证明）→ AH（或 ESP 的认证）；数据完整性 → AH／ESP 的校验；防重播 → AH 的序号机制；密钥与协商 → IKE／SA。问"如何用 IPSec 进行加密、认证与完整性保护"就按这四句答。
SA（安全关联）的概念与两种工作模式：
项目内容
SA 的概念SA 是发送者与接收者之间的一种单向关系，它为其承载的通信提供安全服务。双向通信需要两个 SA（去程与回程各一）；SA 由 SPI 安全参数索引、协议（AH/ESP）、算法、密钥、模式、生命周期等构成
① 传输模式
Transport Mode		只在原 IP 包的数据部分（上层报文）前后插入 AH/ESP，保留原 IP 头——用于主机到主机的端到端保护（两端都是主机时最常用），开销小
② 隧道模式
Tunnel Mode		把整个原 IP 包（含 IP 头）作为载荷封装起来，再加上新的 IP 头——用于站点到站点（网关到网关）的 VPN，可隐藏内部网络拓扑
⚠️ 高频辨析：传输模式保护"数据"、原 IP 头暴露；隧道模式保护"整个包"、外加新 IP 头。看到"用于构建 VPN、隐藏内网"→隧道模式；看到"端到端主机通信、开销小"→传输模式。

五、传输层安全协议 SSL/TLS ⭐⭐

识记 SSL/TLS 的三种基本安全功能服务；领会 SSL 握手协议、SSL 记录协议、TLS 在 SSL 上改进后的优点；综合应用 基于 SSL/TLS 工作原理保证数据传输的安全性。
SSL（Secure Sockets Layer，安全套接层）／TLS（Transport Layer Security，传输层安全）：为网络通信提供安全及数据完整性的一种安全协议，TLS 与 SSL 在传输层对网络连接进行加密。SSL 协议建立在运输层和应用层之间，是提供客户和服务器双方网络应用安全通信的开放式标准。
三种基本的安全功能服务（必背）：
#服务使用的算法作用
1信息加密既有对称加密技术 DES、IDEA，又有非对称加密技术 RSA加密可防止数据中途被窃取（会话密钥用对称、其分发用非对称）
2身份验证验证算法包括 RSA、DSA、ECDSA确认通信对方（尤其服务器）的身份，防假冒站点
3信息完整性校验报文鉴别码（MAC／散列）保证数据未被篡改地到达
SSL 握手协议（位于 SSL 记录协议之上的主要子协议，两个阶段）：
  1. 第一阶段——交换密钥等信息：通信双方通过相互发送 Hello 消息进行初始化（协商协议版本、随机数、密码算法套件，并交换／加密会话密钥）；
  2. 第二阶段——用户身份验证：服务器（必要时也包括客户端）出示数字证书，用 RSA／DSA／ECDSA 完成身份验证，双方确认密钥后握手结束。
SSL 记录协议：在 SSL 协议中，所有要传输的数据都被封装在记录中；记录协议规定了数据传输格式，它包括应用程序提供的信息的压缩、数据验证等。SSL 记录格式五字段：信息类型、主要版本、次要版本、压缩长度、数据段。
TLS 在 SSL 基础上改进后的优点（五条）：
  • 对于消息验证使用密钥散列法 HMAC；
  • 增强的伪随机功能（PRF，密钥扩展更安全）；
  • 改进的（已完成）Finished 消息验证，即"改进的已完成消息验证"；
  • 一致的证书处理；
  • 特定的警报（Alert）消息。
综合应用题的答题骨架：握手两阶段（交换密钥 → 身份验证）＋ 记录协议（压缩、验证、加密封装成记录）
💡 如何用 SSL/TLS 保证数据传输的安全性（综合应用答题模板）：①先在传输层建立安全连接——握手第一阶段用 Hello 消息协商版本与算法并交换密钥信息；②第二阶段用 RSA/DSA/ECDSA 完成身份验证（校验对方证书），杜绝假冒站点与中间人；③随后所有数据封装在记录中，由记录协议完成压缩、数据验证，用对称算法 DES/IDEA 加密保保密性、用报文鉴别码保完整性；④会话密钥一次性使用，即使长期私钥泄露也难以解出历史报文；⑤出现异常时用警报消息立即断开会话（TLS 的 HMAC 与增强伪随机使消息验证更安全）。一句话收尾：SSL/TLS 用"非对称解决认证与密钥分发、对称解决高速加密、散列解决完整性"的三重组合，在不可信网络上搭出一条端到端的可信通道。

六、应用层安全协议：SSH 与 S/MIME ⭐

领会 安全外壳协议 SSH 的组成和启动方法；简单应用 S/MIME 两种安全服务（数字签名、邮件加密）在邮件系统中的工作流程。
① SSH（Secure Shell，安全外壳协议）主要由三部分组成：传输层协议、用户验证协议、连接协议。
组成职责（理解性补充）
传输层协议建立安全连接，完成服务器认证、密钥交换、算法协商与完整性保护（运行在 TCP 之上，默认端口 22）
用户验证协议由服务器验证用户身份（口令、公钥、挑战—应答等）
连接协议在已认证的加密通道上多路复用各种会话：远程登录 shell、端口转发、SFTP 文件传输等
SSH 的启动方法（三种，识记名称）：①使用批处理文件；②使用 SSH 服务配置程序；③使用 NET 命令。
🔑 联系第 1、3 章：SSH 之所以被推荐，是因为它能替代明文的 Telnet（23）与 FTP——把口令与数据全部加密，这正是"文件传输与远程登录安全"的标准防范措施答案之一。
② S/MIME 的两种安全服务与工作流程（简单应用，顺序题常考）：
服务发信方向的处理顺序（8 步）收信方向的处理顺序（10 步）
数字签名
（保证来源与完整性、防抵赖）		发件人用自己的私钥对邮件摘要签名并附加；收件人（或第三方）用发件人的公钥／证书验证
对电子邮件进行签名和加密
（发送流程）
捕获邮件正文→检索唯一的发件人信息→检索唯一的收件人信息→执行签名操作→附加数字签名→执行加密操作→用加密邮件替换原始邮件→发送邮件
对数字签名进行解密和验证
（接收流程）
接收邮件→检索加密邮件→检索唯一的收件人信息→执行解密操作→检索解密后的邮件正文→显示邮件正文→检索数字签名→检索唯一的发件人信息→比较数字签名→验证邮件
⚠️ 顺序要点（易错）：发送时"先签名、后加密"；接收时"先解密、后验签"——两个方向的操作次序正好相反，题目常把这两步调换让你纠错。另外记：签名用发件人私钥，加密用收件人（公钥／会话密钥）。
🔑 对照记忆：PGP／PEM／S-MIME 三个都是"电子邮件安全协议"，差别在实现路线（S/MIME 依托企业 PKI 与 X.509 证书，PGP 采用"信任网 Web of Trust"）。考纲只要求归类与用途，不必深究差别。

七、SET 协议的应用系统框架与分析 ⭐⭐ 案例分析

综合应用 SET 协议的应用系统框架设计及分析（考纲附录题型举例：给出框架图补全参与方 + 说明支付流程 + 比较 SET 与 SSL）。
SET（Secure Electronic Transaction，安全电子交易）是面向信用卡支付的应用层安全协议，其设计目标是：信息保证（数据端到端完整）、报文源真实性（多方认证）、订单信息与个人信息隔离（商家看不到卡号）、协议开放与互操作。
SET 应用系统的六个参与方（框架图必背，"补全框架"就是填这 6 个）：
实线是资金／报文流，虚线是 CA 的证书信任流——框架题按 6 方补全并画出这两类连线
SET 支付流程（一般八步，用于"说明支付过程"）：
  1. 选购与下单：持卡客户在网上商家浏览选购，商家返回订单信息；
  2. 生成支付指令：客户用电子钱包填卡号等支付信息 PI，与订单信息 OI 一起准备发送；
  3. 双重签名：客户对 H(OI) 与 H(PI) 拼接后做双重签名，使商家只能验证 OI、银行只能验证 PI，两者互不可见；
  4. 发送：把 OI + 经商家公钥加密的部分 + PI（客户用支付网关公钥加密）连同自己的支付证书发给商家；
  5. 商家验证并转发：商家用 CA 证书验证客户签名与订单，原样转发 PI（自己无法解密）给支付网关；
  6. 支付网关转换与授权：支付网关解密 PI、把 SET 报文转换为银行网格式，向收单银行／发卡银行请求授权；
  7. 返回授权与确认：发卡行批准后经网关→商家返回授权响应，商家向客户发订单确认并配货；
  8. 清算与对账：日后收单银行向发卡银行请款、完成资金清算，各方依签名记录不可抵赖地对账。
ℹ️ 上述八步是按 SET 通用机制整理的答题骨架（考纲只给了六方参与者的名单）；各步的确切名称与划分请以教材 6.5 与课件原文为准，作答时先写清"六方"再逐步展开即可得分。
SET 与 SSL 的区别（案例分析必答，也是本章最高频的对比题）：
比较项SETSSL / TLS
所处层次应用层安全协议（专门面向电子交易报文）传输层安全协议（在运输层与应用层之间）
保护对象保护交易报文本身，端到端覆盖客户—商家—银行三方保护一条通信通道，只对客户—服务器两点之间的链路安全负责
参与方与认证多方认证：持卡人、商家、支付网关都持有证书，三方互验身份通常只有服务器认证，客户端认证（双向）为可选、部署少
信息隔离用双重签名实现订单信息与个人信息分离——商家看不到卡号，银行看不到订单明细无此机制：商家服务器能读到提交的全部明文表单（含卡号）
不可否认／仲裁交易报文带数字签名，可作支付依据与争议仲裁只保证通道安全，不提供交易级不可抵赖
部署成本复杂、昂贵：需电子钱包软件、各方证书与支付网关改造，故未大规模普及简单、通用：浏览器与服务器内置，无需专用客户端 ⇒ 现实中成为主流（HTTPS）
🔑 一句总结（写在这类题的结尾最出彩）："SSL 解决的是'管道安不安全'，SET 解决的是'交易可不可信'"——SET 以多方认证与双重签名换来交易级安全与隐私隔离，代价是部署复杂；SSL 以通道加密换取通用与易用，但无法阻止商家留存持卡人的支付信息。

八、本章速记小结

  1. 概念与三特点：采用密码算法保证信息安全交换的协议；保密性、完整性、认证性；按功能分五类（密钥建立／认证／认证与密钥交换／电子商务／安全通信）。
  2. 分层归属：网络层 IPSec；传输层 SSL/TLS；应用层 SET、S-HTTP、PGP、S/MIME、PEM、SSH、Kerberos。
  3. IPSec 四组成：ESP（加密＋完整性）、AH（只完整性与源认证、防重播）、SA（单向关系，双向要两个）、IKE（协商 SA 与密钥）；两种模式：传输模式（留原 IP 头）／隧道模式（封装整包＋新 IP 头，用于 VPN）。
  4. SSL/TLS 三种服务：信息加密（DES、IDEA + RSA）、身份验证（RSA、DSA、ECDSA）、完整性校验；握手两阶段（Hello 交换密钥 → 身份验证）、记录协议（压缩、验证；记录格式＝信息类型·主版本·次版本·压缩长度·数据段）；TLS 五改进（HMAC、伪随机、Finished 验证、一致证书处理、特定警报）。
  5. SSH 三组成（传输层／用户验证／连接协议）＋三种启动方法（批处理文件、SSH 服务配置程序、NET 命令）。
  6. S/MIME 两服务：先签名后加密发送（8 步）／先解密后验签接收（10 步）。
  7. SET 六方：持卡客户、网上商家、支付网关、收单银行、发卡银行、验证中心；核心机制双重签名；与 SSL 的本质差别＝通道安全 vs 交易可信。
