一、网络数据库的安全策略与安全需求 ⭐⭐

识记 网络数据库的安全策略；领会 网络数据库的安全需求。
安全策略（四条）——从数据库系统的存在性、可用性、机密性和完整性几个方面着重考虑，数据库系统至少具有以下安全策略：
#策略含义主要技术手段
1① 保证数据库的存在安全数据库本身（数据文件、结构、服务）不被破坏、不被盗走、不丢失物理与环境安全、访问控制、防病毒与防入侵（第 2、8、9 章）、备份
2② 保证数据库的可用性授权用户在需要时能正常访问和使用数据与服务冗余与集群、容灾、备份恢复、性能与容量管理、抗拒绝服务
3③ 保障数据库系统的机密性数据不泄露给未授权者（含被窃听、被拖库）身份验证、加密与视图／列级控制、强制访问控制、审计
4④ 保证数据库的完整性数据未被未授权篡改，且符合语义约束（正确、一致）约束与触发器、事务与并发控制、基于完整性的强制策略、日志与审计
安全需求（七条，"可将数据库安全问题定义为以下内容"）：
#需求关注点
1物理数据库的完整性数据文件、存储设备、机房环境不被物理破坏（灾害、盗抢、误操作删文件）
2逻辑数据库的完整性模式与数据的一致性、约束不被破坏（关系结构、参照完整性、业务规则）
3元素安全性细粒度到数据元素（表、行、列、字段值）的保护与授权
4可审计性谁在何时做了什么可追溯（审计日志、操作留痕、责任认定）
5访问控制按策略限制主体对客体的操作（DAC／MAC／RBAC，见第 8 章）
6身份验证确认连接者与用户的真实身份（口令、证书、操作系统／网络级认证）
7可用性服务持续可提供、数据可恢复（备份与容灾是本章第四节）
🔑 记忆组合：策略四条＝"存在、可用、机密、完整"（题干常给四个方面让你列策略）；需求七条＝"两完整（物理／逻辑）＋元素＋审计＋访问控制＋身份验证＋可用"。两者是"目标 vs 具体问题清单"的关系。

二、访问控制模型：两种强制策略与两条控制原则 ⭐⭐

识记 强制访问控制的两种强制策略、基于完整性的强制策略的两条控制原则。
强制访问控制策略可以分为两类：基于保密性的强制策略和基于完整性的强制策略。
基于完整性的强制策略依据以下两条原则控制主体对客体的访问请求：（1）不能向下读；（2）不能向上写。
策略类型要防的事允许／禁止的方向一句话理由
基于保密性的强制策略防泄露（秘密往下跑）禁 上读、禁 下写；允 下读、允 上写不能看比自已高的（防刺探），不能把内容写到低级客体（防外抛）
基于完整性的强制策略防篡改／污染（脏数据往上爬）禁 下读、禁 上写；允 上读、允 下写两条控制原则的原文；不采信低可信数据，不许低级主体改高级数据
两套策略方向正好相反：保密性管"别往外漏"，完整性管"别往里灌"——考试常问"基于完整性的两条原则"，答案就是不能向下读、不能向上写
⚠️ 常见错答：把保密性与完整性的禁止方向写反。校验方法——"向下读"会引入低可信数据（伤完整性）故完整性禁它；"向上写"会污染高可信数据（同样伤完整性）故完整性禁它；泄露则是"把高级内容写到低级"（下写）与"偷看高级"（上读），由保密性禁止。

三、多级安全模型的多实例问题与完整性锁（领会）

领会 多级安全模型的多实例问题、完整性锁的作用。
多级安全模型：把主体与客体都分到多个安全等级（如绝密／机密／秘密／公开）并按强制策略判定的模型。当同一张表要同时存放不同密级的数据时，就出现多实例（multiple instantiation）问题——同一逻辑实体的多个副本因密级不同而分散，导致一致性与授权困难。
多实例问题主要表现在以下三个方面：
方面含义带来的麻烦
① 多实例关系同一关系（表）因密级不同被分成多个实例关系（如"人员表-秘密级"与"人员表-机密级"）用户看不到全貌；跨密级的查询、约束与参照完整性难以统一维护
② 多实例元组同一元组（行）在不同密级关系中出现多个副本更新一个副本会造成数据不一致；删除时容易漏删低密级副本（残留泄露）
③ 多实例元素同一元组中的某个数据元素（字段值）有多个密级版本字段级密级使视图、授权与审计复杂化，聚合统计易失真
完整性锁的作用（识记句）：完整性锁的目的是能够让用户使用任何数据库管理器，实施或授权对敏感数据的访问。
🔑 理解补充：完整性锁＝把数据项与"谁能读写它"的安全属性锁在一起，使得无论用户通过哪种数据库管理器（客户端工具、应用、命令行）访问，安全规则都一致生效——从而既防止绕过某个工具的越权，又支持由授权者把访问权再授予他人。答"作用"时把上面那句原文写上即可得分。

四、数据库服务器的安全漏洞（领会）⭐

领会 数据库的服务器安全漏洞。
数据库服务器的安全漏洞种类繁多、危害性严重，是数据库系统受到攻击的主要原因。按来源大致分为 4 类：
#漏洞来源典型表现处置方向
1默认安装漏洞默认账号／空口令或弱口令（如 sa、sys）、默认监听端口与示例库、安装时遗留的高权限账号装完立刻改口令、删除示例与无用账号、改默认端口、限制监听地址
2人为使用漏洞DBA 随意授予dba／超级权限、口令共享与外泄、把生产库开放给个人电脑、不记日志、随意导数据职责分离与最小特权、账号专用与审批、集中审计、口令策略
3数据库设计缺陷模式设计不合理导致约束缺失／权限挂错、视图与存储过程暴露敏感列、SQL 注入（拼接语句未校验）安全建模阶段就定分级与授权方案、用参数化语句与最小视图、代码审计
4数据库产品漏洞DBMS 自身程序缺陷与后门、扩展存储过程（如命令执行）、补丁未及时发布造成的已知漏洞跟踪补丁并按测试—上线流程更新、关闭不必要的组件与扩展、打基线加固配置
🔑 口诀记四类来源："默认—人为—设计—产品"（从"装好那一刻"到"用的过程"到"设计"再到"软件本身"）。这条链正好说明：数据库安全不能只靠 DBMS，必须与操作系统、网络（第 8 章防火墙）、入侵防御（第 9 章）层层配合。

五、备份方案的组成与备份方法分类（识记）⭐⭐

识记 系统备份方案的组成、网络数据库备份的方法和分类；领会 应用需求与备份方法选择、软件备份功能组成。
一个完整的系统备份方案应由 4 部分组成（必背）：
① 备份硬件② 备份软件③ 日常备份制度④ 灾难恢复措施
组成包括什么易被忽略的点
① 备份硬件磁带机／磁带库、磁盘阵列与备份一体机、NAS／SAN、异地存储与介质保管设备硬件本身会坏 ⇒ 介质也要冗余（异地、多份）
② 备份软件数据库备份工具（SQL*PLUS、OEM、RMAN 等）与企业级备份管理软件（调度、介质管理、恢复）只备份不验证等于没备份 ⇒ 需定期做恢复测试
③ 日常备份制度备份周期与时间表、保留与轮换策略（如按周轮换、月度长期保留）、责任人与交接、记录台账把"谁来备、何时备、存多久"写成制度而非口头习惯
④ 灾难恢复措施恢复流程与预案、RTO／RPO 目标、备用站点与切换演练、灾难发生时的组织与通报备份是手段，恢复才是目的——必须演练过
网络数据库的备份种类繁多，根据不同需求可以选择相应的最佳备份方法。常用的备份方法有以下几种（五对）：
#方法（分类角度）含义取舍
1物理备份 与 逻辑备份物理＝复制数据文件／控制文件／日志等底层文件；逻辑＝导出对象与数据（SQL／转储文件），与存储结构无关物理恢复快、可整库还原；逻辑灵活可跨版本／挑对象，但大对象慢
2一致性备份 与 不一致性备份一致性＝备份得到的数据在某一时刻是自洽完整的；不一致＝备份期间仍在写入，各文件不在同一时间点不一致备份必须配合归档日志前滚才能恢复一致
3全数据库备份 与 部分数据库备份全库＝整个数据库一次备完；部分＝只备关键表空间／数据文件／库全库耗时长、占用大；部分备份灵活、窗口短，需规划组合
4联机备份 与 脱机备份联机＝数据库打开状态下备份（＝热备份）；脱机＝数据库正常关闭后备份（＝冷备份）联机不停业务但要归档模式；脱机简单一致但要停机（详见下一节）
5不同工具的备份按使用的工具区分：SQL*PLUS／OEM 备份向导、RMAN、第三方备份软件、操作系统复制命令等工具决定能否点恢复、能否压缩与并行、能否集中调度
软件备份的功能组成（六项，教材原列）：①磁带驱动器的管理；②磁带库的管理；③备份数据的管理；④数据格式的管理；⑤备份策略制定；⑥数据恢复工作。
🔑 记"两管硬件（驱动器、库）+ 两管数据（备份数据、数据格式）+ 一策略 + 一恢复"。选方法时按业务能否停机、允许丢多少数据（RPO）、多久要恢复（RTO）、存储预算四个问题定：能停 ⇒ 脱机冷备；不能停 ⇒ 联机热备＋归档；量大 ⇒ 全库低频＋部分高频组合。
ℹ️ 业界还常用完全备份／增量备份／差异备份这组概念（增量只备上次备份后的变化、差异只备上次完全备份后的变化）。教材以"全数据库备份和部分数据库备份"表述，答题以教材口径为主，把这组作为补充说明即可。

六、物理热备份与冷备份的实施方法和特点（简单应用）⭐⭐

简单应用 物理热备份和冷备份的实施方法和特点。
物理热备份也是联机备份，是指在数据库打开状态下进行的备份，只能运行在归档模式下，使用联机备份时要避免出现数据裂块（备份期间页被改写导致块内不一致，故需"置为备份模式"）。
热备份的使用方法（教材步骤，应用题按此写）：可以使用 SQL*PLUS 程序和 OEM 中的备份向导进行热备份。在进行热备份之前，应将数据库置为归档模式——该操作必须以 DBA 的角色重启数据库并进入 MOUNT 状态，然后执行 ALTER DATABASE 命令修改数据库的归档模式。在设置完数据库归档模式后，再将数据库打开，将数据库置为备份模式，这样数据库文件在备份期间不会改变。
① 以 DBA 角色重启并进入 MOUNT→② ALTER DATABASE 改为归档模式→③ 打开数据库→④ 将表空间／数据文件置为备份模式→⑤ 操作系统复制文件→⑥ 结束备份模式并备份归档日志 
-- 关键操作示意（Oracle 风格，与教材步骤对应）
STARTUP MOUNT;                          -- ① 以 DBA 角色重启，先进入 MOUNT 状态
ALTER DATABASE ARCHIVELOG;              ALTER DATABASE OPEN;  -- ② 改为归档模式后 ③ 打开数据库
ALTER TABLESPACE ts_data BEGIN BACKUP;  -- ④ 置为备份模式：备份期间文件不会被改变
-- ⑤ 用操作系统命令复制该表空间的数据文件（此时数据库是打开的）
ALTER TABLESPACE ts_data END BACKUP;    -- ⑥ 结束备份模式，再备份归档日志以便点恢复
热备份的特点（五条，必背）：
  1. 备份时数据库可以是打开的（业务不中断，属联机备份）；
  2. 热备份可以用来进行点恢复（配合归档日志可恢复到指定时刻）；
  3. 初始化参数文件、归档日志在数据库正常运行时是关闭的（不随热备份一起做），可用操作系统命令复制；
  4. 可以对几乎所有的数据库实体进行恢复；
  5. 恢复速度快，大多数情况下在数据库工作时就可以完成恢复。
冷备份（脱机备份）的实施与特点（对照记忆）：在数据库正常关闭后，用操作系统命令复制全部数据文件、控制文件、联机重做日志与初始化参数文件；打开数据库恢复。它一致性天然成立、操作简单，但必须停机，且只能恢复到备份时刻（不能点恢复，因为其间没有归档日志可前滚）。
比较项热备份（联机）冷备份（脱机）
数据库状态打开状态下备份，业务继续运行关闭（正常关闭）后复制文件
前提条件必须运行在归档模式；须置／结束备份模式避免数据裂块无归档要求；必须干净关闭（异常关闭后的文件集不可用）
能否点恢复能（备份 + 归档日志前滚到指定时刻）不能，只能回到备份时刻，丢失其后的改动
对业务影响不停机，但占用 I/O、性能有影响；操作复杂、易出错需停机，影响可用性；操作简单一致
恢复范围与速度可恢复几乎所有数据库实体，恢复快、多数可边运行边恢复只能整库（或整组文件）还原，恢复需再次停机
适用场景7×24 关键业务系统（银行、电商、生产库）可停机维护的小型库、数据仓库、初始化基线备份
💡 应用题（"为某单位设计数据库备份方案"）的四段答法：①需求分析——能否停机、可容忍丢失多少数据（RPO）、要求多久恢复（RTO）、数据量与增长；②方案组成——四件套（硬件／软件／日常备份制度／灾难恢复措施）分别选什么；③方法与排程——不能停 ⇒ 热备份（先置归档模式，表空间 BEGIN/END BACKUP）＋每日归档日志；能停 ⇒ 周末冷备份为基线，工作日增量；关键表空间做部分备份缩短窗口；介质异地两份；④验证与预案——软件备份六功能（驱动器、库、备份数据、数据格式、策略、恢复）齐备，每季度做恢复演练，写明切换流程与责任人。收尾一句："备份的价值取决于能不能恢复，所以灾难恢复措施与演练是方案的组成部分，而不是附注。"

七、本章速记小结

  1. 四项安全策略：存在安全、可用性、机密性、完整性（从这四个方面着重考虑）。
  2. 七项安全需求：物理完整性、逻辑完整性、元素安全性、可审计性、访问控制、身份验证、可用性。
  3. 两种强制策略：基于保密性（禁上读、禁下写）、基于完整性（不能向下读、不能向上写）。
  4. 多实例问题三方面：多实例关系、多实例元组、多实例元素；完整性锁＝让用户使用任何数据库管理器都能实施或授权对敏感数据的访问。
  5. 服务器漏洞四来源：默认安装、人为使用、数据库设计缺陷、数据库产品。
  6. 备份方案四组成：硬件、软件、日常备份制度、灾难恢复措施；五对备份方法：物理／逻辑、一致／不一致、全库／部分、联机／脱机、不同工具；软件备份六功能：磁带驱动器、磁带库、备份数据、数据格式、策略制定、数据恢复。
  7. 热备份＝联机备份，只能在归档模式下做，流程 MOUNT → ALTER DATABASE 归档 → 打开 → 置备份模式 → 复制 → 结束备份模式；五特点记住"开着备、能点恢复、参数文件与归档日志靠 OS 复制、几乎全能恢复、恢复快"。冷备份简单一致但停机、不能点恢复。
🎯 6 学时分配：安全策略与需求 1.5 → 强制访问控制两策略与多实例 1.5 → 服务器漏洞 0.5 → 备份组成与方法 1.5 → 冷热备份实施与特点 + 方案设计 1。整章只考清单与实施，计算量为零，属于"背了就有分"的收官章。⚠️ 页首"✂️ 10.3、10.5、10.6"按教材节号统计，但考纲考核知识点（一）～（四）全部要求掌握（含"数据库服务器安全漏洞"），以清单为准。
