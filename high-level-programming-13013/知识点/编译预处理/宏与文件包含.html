第 9 章 · 宏定义与文件包含

编译预处理只有一句话：在编译之前做纯文本替换。它不理解类型、不做计算、不分配内存——所以 #define P(x) x/x 传进 4+6 得到的不是 1，而是 11。这一章两套卷共 5 道题，全是"记住规则就得分"。

一、预处理是什么：编译前的三类命令

预处理（编译预处理）是在正式编译之前由预处理程序对源程序做的"文字加工"，结果仍然是一个源程序文件，再交给编译器。
类别命令作用
宏定义#define、#undef定义 / 取消一个"名字替换规则"
文件包含#include把另一个文件的全部内容复制到本行位置
条件编译#if、#ifdef、#ifndef、#else、#elif、#endif按条件决定"哪几行参与编译"
三条共同点：① 都以 # 开头，独占一行；② 行尾不加分号（加了分号，分号也会被当成内容替换进去）；③ 它们不是 C 语句，预处理后就不存在了。

二、无参宏：#define N 10

#define PI 3.14159
#define N  10
#define MAX 100

int a[N];              /* 预处理后变成 int a[10]; */
double s = PI * r * r; /* 预处理后变成 3.14159 * r * r */
  1. 纯文本替换：宏名出现的地方，原样换成后面的字符序列，不做任何计算。
  2. 不分配内存、不做类型检查：N 没有类型，替换完才参与编译。
  3. 行尾不加分号：写成 #define N 10; 时，int a[N]; 会展开成 int a[10;]; 直接报错。
  4. 作用域：从定义处起，到本文件结束；可以用 #undef N 提前取消。
  5. 命名习惯：宏名一般全大写，与变量名区分。
宏定义可以嵌套引用：#define A 2 后再写 #define B (A + 3)，则 B 展开为 (2 + 3)——替换是逐层进行的。

三、带参宏：纯文本替换的陷阱

带参宏看起来像函数，但它绝不是函数：形参没有类型，调用时把实参原样抄进去，然后整体替换。 
#define S(a, b) ((a) * (b))     /* 正确写法：参数和整体都加括号 */

m = S(x + 1, y);                /* 展开为 m = ((x + 1) * (y)); */
如果不加括号，就会出这些事： 
#define P(x) x/x
printf("%d\n", P(4 + 6));       /* 展开为 4 + 6/4 + 6 = 4 + 1 + 6 = 11 */
11
宏定义调用实际展开结果
#define P(x) x/xP(4+6)4+6/4+611（不是 1）
#define SQ(x) x*xSQ(a+1)a+1*a+12a+1（不是 (a+1)²）
#define SQ(x) ((x)*(x))SQ(a+1)((a+1)*(a+1))正确
2025.10 真题·第 14 题 #define P(x) x/x，P(4+6) → 4+6/4+6 = 4 + 1 + 6 = 11（答案 C）。
2026.4 真题·第 14 题 #define S(p,q) p*q，m=S(x,y); —— 按"实参逐字替换形参"的原则，p 换成 x、q 换成 y（官方答案 C）。
带参宏的三个硬规则：① 宏名与左括号之间不能有空格——#define S (a,b) 会被当成"无参宏 S 替换成 (a,b)"；② 每个参数都要加括号；③ 整个表达式再加一层括号。
还要小心副作用：#define MAX(a,b) ((a)>(b)?(a):(b)) 里，MAX(i++, j++) 会让 i 或 j 自增两次——宏的参数被求值多次，这是函数不会有的问题。

四、宏与函数的区别

对比项宏（带参宏）函数
处理阶段预处理（编译之前）编译、链接，运行时调用
类型检查没有有
参数类型不写类型必须写类型
是否分配空间不分配调用时分配栈空间
代码长度每展开一次就复制一份，程序变长只有一份
执行速度快（没有调用开销）有参数传递、返回的开销
参数副作用可能被求值多次只求值一次
一句话：宏是"用空间换时间、用灵活换安全"。简单的常量、短小表达式用宏；逻辑复杂、需要类型检查的，一律用函数。

五、文件包含：#include

#include <stdio.h>       /* 尖括号：到系统目录（库目录）找 */
#include "myhead.h"      /* 双引号：先到当前目录找，找不到再去系统目录 */
写法查找顺序适用
#include <文件名>只在系统目录（标准库头文件所在处）找标准库头文件：stdio.h、string.h、math.h
#include "文件名"先在当前源文件所在目录找，再找系统目录自己写的头文件
作用：把被包含文件的全部内容，原样"复制"到 #include 命令出现的位置上。
2026.4 真题·第 23 题 填空答案就是"复制"。
2025.10 真题·第 23 题 使用库函数前要包含相应的"头文件"。
头文件里通常放什么：函数声明（原型）、宏定义、结构体/共用体/枚举类型定义、typedef、extern 全局变量声明。不要放函数定义——被多个文件包含时会重复定义。
一个 #include 只能包含一个文件，不能写 #include <a.h, b.h>。想包含多个就写多行。
重复包含的经典防护（背下来）： 
#ifndef MYHEAD_H
#define MYHEAD_H
/* 头文件内容 */
#endif
第一次包含时 MYHEAD_H 没定义 → 内容被编入并定义它；第二次再包含时它已定义 → 整段被跳过。

六、条件编译

条件编译让"同一份源程序"按条件编出不同的目标代码，最典型的用途是调试开关和多平台适配。 ① #ifdef / #ifndef（判断有没有定义过某个宏）： 
#define DEBUG 1

#ifdef DEBUG
    printf("x = %d\n", x);      /* 只有定义了 DEBUG 才编译这一行 */
#endif

#ifndef PI
#define PI 3.14159
#endif
② #if / #elif / #else（对常量表达式求值）： 
#define LEVEL 2

#if LEVEL == 1
    printf("初级\n");
#elif LEVEL == 2
    printf("中级\n");
#else
    printf("高级\n");
#endif
③ 嵌套使用：条件编译可以多层嵌套，每层都要有配对的 #endif。
2025.10 真题·第 24 题 条件编译可以有效地提高程序的 可移植性（也答"灵活性"），使同一个源程序可提供各种不同的版本。
记忆点：条件编译 = 按"机型 / 环境 / 版本"裁剪代码 → 可移植性；这和"宏 = 纯文本替换""include = 复制"是三条并列的送分填空。

七、本章小结与真题呼应

四条主线：
① 预处理在编译之前完成，命令以 # 开头、不加分号、不是 C 语句；
② 宏是纯文本替换——P(4+6) 展开成 4+6/4+6 得 11；参数加括号、整体加括号、宏名与括号间不留空格；
③ #include < > 找系统目录、#include " " 先找当前目录；作用是复制到本行位置；
④ 条件编译的三种形式与"提高可移植性"的标准答法。

两套卷本章的题：2026.4-14 带参宏展开（C）、2026.4-23 include 是复制、2025.10-14 P(4+6) = 11（C）、2025.10-23 包含头文件、2025.10-24 条件编译提高可移植性。
