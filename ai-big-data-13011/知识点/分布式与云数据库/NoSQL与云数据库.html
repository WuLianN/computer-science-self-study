一、数据库的概念（识记）

识记 数据库的概念。
数据库（Database, DB）：是长期存储在计算机内的、有组织的、可共享的、统一管理的数据集合。四个限定词一个都不能漏：长期存储、有组织（按数据模型组织）、共享（多用户多应用共用）、统一管理（由 DBMS 控制）。
相关概念：DBMS（数据库管理系统）——位于用户与操作系统之间的数据管理软件，负责定义、建立、操纵、维护与控制数据（MySQL、Oracle）；DBS（数据库系统）= 数据库 + DBMS + 应用 + 数据库管理员（DBA）+ 硬件；关系数据库——以关系（二维表）模型组织数据，用 SQL 操作，遵守ACID（原子性、一致性、隔离性、持久性）与三范式。
🔗 与 13009 的衔接：三级模式两级映像、完整性约束等在《数据库原理与应用》里已学过；本章只需把关系数据库当作"被挑战的对象"来对比记忆。

二、NoSQL 的由来与体系架构层次（识记）⭐

识记 NoSQL 的体系架构层次。
名称：NoSQL = "Not Only SQL"（不仅仅是 SQL），指非关系型的、分布式的、一般不保证强一致性的数据库系统，也常直接理解为"非关系型数据库"。
为什么需要 NoSQL（应对关系数据库的四类瓶颈）：①海量数据（TB/PB 级）单机存不下、垂直扩容成本指数上升；②高并发读写（如秒上万次的电商/社交访问）受本地磁盘与锁竞争限制；③数据类型多样（半/非结构化、字段动态变化）难以用固定表结构表达；④需要在线水平扩展与高可用，而传统主从复制与 ACID 强一致成为扩展瓶颈。
NoSQL 的一般特点：①可扩展（去共享、水平扩展、支持动态模式）；②支持多种数据类型（键值、文档、列族、图形）；③支持分布式计算与存储，靠框架而非单机；④高可用性（提供 BASE 而非 ACID，最终一致）；⑤数据模型简单（无复杂表关系、通常不支持或不强调 Join、无完整事务）；⑥性能高（键值直接寻址、内存/缓存友好）。
体系架构层次（自下而上四层，识记框架）：
层次解决什么典型机制
① 分布式存储层数据放在哪、如何容错底层分布式文件系统（HDFS）、对象存储；副本复制、日志与检查点
② 数据分布与扩展层怎么水平扩展数据分片/分区（哈希、范围、一致性哈希）、虚拟节点、自动再平衡、无共享（Shared-Nothing）架构
③ 数据模型层用什么结构表达数据键值 / 列族 / 文档 / 图形四种模型；模式灵活（schema-free）、多版本
④ 一致性与服务层读写语义与协调CAP/BASE 取舍、Quorum（N/R/W）、向量时钟、ZooKeeper 协调选主；接口层（API、类 SQL 查询、MapReduce 访问）
⚠️ 若教材把"体系架构"表述为三层（存储层 / 数据模型层 / 访问接口层），按三层答也得分——记住"存储在下、模型在中、接口在上，一致性贯穿其中"这条主线即可。

三、NoSQL 的四种分类（识记）⭐⭐

识记 NoSQL 的分类。
类型数据模型优点缺点代表产品典型场景
① 键值（Key-Value）哈希表：key → value，value 不解析结构最简单、读写最快、易扩展无法按内容查询（只能按 key）、无复杂约束Redis、Memcached、Voldemort、Dynamo、LevelDB缓存、会话、计数器、购物车
② 列族 / 列存储（Column-Family / Column-Oriented）按列族存储，行键 + 列族 + 列限定符 + 时间戳适合海量分布式数据、列聚合查询高效、稀疏存储省空间不支持复杂关联与事务、跨行原子性差HBase、Cassandra、Hive（列式存储思想）日志、监控指标、用户行为、消息存储
③ 文档型（Document-Oriented）以 JSON/BSON/XML 自包含文档为单位模式灵活、贴近对象模型、可嵌套、查询能力较强事务与关联弱、文档过大有性能问题MongoDB、CouchDB、Couchbase内容管理、商品目录、用户画像、移动后端
④ 图形（Graph）顶点 + 边（关系）+ 属性，关系是一等公民擅长表达与查询复杂网络关系，遍历效率高（免"图计算爆炸"）生态较小、超大规模分析不如批处理Neo4j、InfoGrid、JanusGraph、GraphDB社交网络、推荐关系、知识图谱、风控关联
🎯 单选口诀："键值最快、列族最能扛量、文档最灵活、图形最懂关系"。题目给产品名让你选类型：Redis→键值；HBase/Cassandra→列族；MongoDB/CouchDB→文档；Neo4j→图形。

四、NoSQL 与关系数据库的区别与关系（领会）⭐

领会 NoSQL 与关系数据库的区别和关系。
比较维度关系数据库（MySQL/Oracle）NoSQL（HBase/MongoDB/Redis）
数据模型二维表，行列表结构固定键值 / 列族 / 文档 / 图形，模型多样
模式 Schema强模式（写时模式，先定义列与约束）弱模式 / 无模式（读时模式，可动态增列）
一致性 / 事务ACID 强一致，支持多行事务BASE 最终一致，多为单行/单文档原子（弱事务）
扩展方式垂直扩展（换更强单机），分库分表复杂水平扩展（加节点、自动分片）
查询语言SQL，支持复杂 Join、聚合、子查询各自 API/类 SQL，不支持或弱支持 Join
性能侧重复杂事务与关联查询、中小规模海量数据的高并发读写与扫描
规范化遵循三范式减少冗余常反范式、用冗余换性能
典型用途OLTP 业务系统、财务、订单大数据、实时 Web、移动、IoT、缓存
两者的"关系"（不要只答区别，这半问常被漏掉）：①不是替代而是互补：NoSQL 解决的是关系数据库不擅长的海量、高并发、灵活模式场景，业务核心事务仍由关系库承担；②常混合部署：典型架构是"关系库（业务）+ 缓存（Redis）+ NoSQL（日志/行为）"分层，或用 ETL/Sqoop 在两者间搬数据；③技术上互相借鉴：NoSQL 借鉴关系库的索引、SQL 化查询（Hive/HQL、CQL），关系库也吸收分布式与 NoSQL 特性（NewSQL、MySQL 支持 JSON）；④底层可复用：HBase 构建在 HDFS 之上、Hive 用关系式接口访问 Hadoop 数据。

五、CAP 定理与 BASE 理论（领会）

领会 NoSQL 的理论基础（与关系数据库的区别）。
CAP 定理：一个分布式系统最多只能同时满足以下三项中的两项——C 一致性（Consistency）：所有节点同一时刻看到的数据相同；A 可用性（Availability）：每个请求都能得到（非错误）响应；P 分区容错性（Partition tolerance）：网络分区发生时系统仍能继续运行。由于分布式环境中网络分区不可避免，P 必选，所以实际是在 CP 与 AP 之间取舍。
取舍含义代表系统
CP（弃可用性）分区时宁可拒绝服务也要保证数据一致ZooKeeper、HBase、MongoDB（默认写关注）、关系型分布式数据库
AP（弃强一致）分区时仍可读写，事后收敛到一致（最终一致）Cassandra、Dynamo、Eureka、多数键值缓存
AC（不分区）单机/强同步环境，实际分布式中不可取传统单机关系数据库（严格说不是分布式场景）
BASE 理论（对 ACID 的放松，NoSQL 的设计哲学）：BAsically Available（基本可用：整体性能可下降但保证核心功能，如降级、限流、超时返回）；Soft state（软状态：允许中间状态存在，状态间同步可有延迟）；Eventually consistent（最终一致：经过一段时间后数据达到一致，不要求即时一致）。
🔑 记忆：ACID 是"事务级强一致"，BASE 是"柔性可用 + 最终一致"；BASE 不是放弃一致性，而是用可用性换取可扩展性与性能，把一致性推迟到"最终"。

六、云数据库的概念与特点（识记）⭐

识记 云数据库的概念和特点。
概念：云数据库是部署和虚拟化在云计算环境中的数据库，是在云计算大背景下发展起来的一种新兴的共享基础架构方法——它极大增强了数据库的存储能力，消除了人员、硬件、软件的重复配置，让软硬件升级变得容易。用户按需申请、通过网络访问、按使用量付费，无需自建与维护底层设施。
特点（识记·八条）：①动态可扩展 / 高可扩展性（弹性伸缩，随业务增删节点）；②高可用性（多副本、自动故障切换，消除单点）；③多租户（资源共享又相互隔离）；④较低的使用成本（按需付费、免初始硬件投入）；⑤易用性（提供管理界面与标准接口，兼容既有 SQL/协议）；⑥高性能（读写分离、缓存、并行）；⑦免维护（备份、升级、监控由服务商完成）；⑧安全（SSL 连接、IP 白名单、访问控制、操作审计）；另常加"支持资源有效分发"。
主流云数据库产品（识记，能配对厂商）：
厂商产品要点
AmazonRDS、DynamoDB、Aurora、Redshift、SimpleDB/S3RDS 托管关系库；DynamoDB 是键值/文档型 NoSQL（CAP 中 AP 代表）
MicrosoftSQL Azure / Azure SQL Database属关系型云数据库，支持 T-SQL 管理创建与操作，可在本地开发后部署上云；支持大量典型数据类型；支持云中局部事务但不支持分布式事务
GoogleBigtable、Cloud SQL、Spanner、BigQueryBigtable 是列族分布式存储，HBase 的原型
阿里 / 腾讯 / 华为UMP（早期）、RDS / PolarDB / OceanBase；TDSQL/CDB；GaussDB本章 UMP 即阿里核心系统数据库团队设计的低成本高性能 MySQL 云数据库方案
⚠️ 易错：云数据库没有专属于自己的数据模型——它可以采用关系模型，也可以是非关系模型（键值/文档/列族）；很多云数据库后端直接复用现有关系库或 NoSQL 引擎。判断"云数据库 = NoSQL"是错误的。

七、UMP 系统：架构角色与功能（领会）⭐⭐ 本章难点

领会 UMP 系统架构中的角色及功能。
概述：UMP（Unified MySQL Platform）由阿里集团核心系统数据库团队设计与实现，是一个低成本、高性能的 MySQL 云数据库方案，关键模块用 Erlang 实现。开发者通过网络从平台申请 MySQL 实例资源，用单一入口访问数据；系统把服务器资源划分为资源池，以资源池为单位分配给 MySQL 实例，从而实现资源虚拟化、降低整体成本。用户按规模分三类：小数据量/小流量用户（多用户共享一个实例）、中等规模用户（独占一个实例）、需要分库分表的用户（多个实例共享同一物理机）。
架构设计原则（四条）：①保持单一的系统对外入口，内部维护单一的资源池；②消除单点故障，保证服务高可用；③保证系统具有良好的可伸缩性，能动态增删计算与存储节点；④保证用户资源弹性可伸缩、资源之间相互隔离，确保应用与数据安全。
（一）系统中的七种角色及其功能（难点·必背清单）：
角色功能
① Controller 服务器提供各种管理服务：集群成员管理、元数据存储、MySQL 实例管理、故障恢复、备份、迁移、扩容。其上运行一组 Mnesia 分布式数据库保存元数据（集群成员、用户配置与状态、用户名→后端 MySQL 实例地址的"路由表"）；部署多台避免单点，由 ZooKeeper 分布式锁选出一个"总管"负责调度与监控
② Proxy 服务器向用户提供访问 MySQL 的服务（唯一数据入口）：除数据路由基本功能外，还实现屏蔽 MySQL 实例故障、读写分离、分库分表、资源隔离（限制 QPS）、记录用户访问日志等
③ Agent 服务器部署在 MySQL 实例所在机器上的"探针/执行者"：接收 Controller 指令，负责本机 MySQL 实例的创建、配置、启停、监控与状态上报（心跳），执行备份、迁移等本地操作
④ Web 控制台给用户和管理员的操作界面：申请/管理实例、查看状态与性能、执行运维操作，并提供 API 接口（与 Controller 交互）
⑤ 日志分析服务器收集并分析 Proxy 记录的用户访问日志：统计 SQL 执行次数、耗时、错误等，用于问题定位、性能分析与计费（常借助 RabbitMQ 消息队列异步传输）
⑥ 信息统计服务器统计系统整体运行信息：各实例的容量、性能、资源使用与业务指标，供监控、报表与资源调度决策
⑦ 愚公系统数据迁移/同步工具：负责把原有（如 Oracle/其他 MySQL 实例）数据迁移到 UMP，以及实例间的数据搬迁、扩容时的数据重分布
（二）依赖的四个开源组件：Mnesia（Erlang 自带的分布式数据库，存元数据）、LVS（Linux 虚拟服务器，做负载均衡、保证 Proxy 单一入口高可用）、RabbitMQ（消息队列，异步传递日志与控制消息）、ZooKeeper（分布式锁/选主，从多台 Controller 中选出"总管"）。
（三）系统功能（对用户透明的七项）：容灾（主从热备、故障自动切换）、读写分离（Proxy 按 SQL 类型路由）、分库分表、资源管理、资源调度、资源隔离（Cgroup 限制 CPU/内存/IO + Proxy 限制 QPS）、数据安全（SSL 连接、IP 白名单、操作日志、SQL 拦截）。
UMP 系统架构与角色关系（简答"UMP 架构中的角色及功能"按七角色逐条写）
🧠 记忆法：把 UMP 想成一个"云上 DBA 团队"——Controller 是领导（管元数据与决策）、Proxy 是前台（唯一入口 + 路由）、Agent 是现场工人（本机实例操作）、Web 控制台是门面（用户下单）、日志分析与信息统计是记账与体检、愚公是搬家队；四个开源件是工具：Mnesia 记事本、LVS 分流闸、RabbitMQ 传话筒、ZooKeeper 选班长。

八、本章速记小结

  1. 数据库四限定：长期存储、有组织、可共享、统一管理。
  2. NoSQL = Not Only SQL，为海量 + 高并发 + 多类型 + 水平扩展而生；架构四层：存储 → 分片 → 模型 → 一致性/接口。
  3. 四类：键值（Redis）、列族（HBase/Cassandra）、文档（MongoDB）、图形（Neo4j）——"最快 / 最能扛量 / 最灵活 / 最懂关系"。
  4. 与关系库：模型、模式、ACID vs BASE、垂直 vs 水平、SQL vs API、范式 vs 反范式；关系是互补混用、相互借鉴、底层复用。
  5. CAP 三选二（P 必选 → CP / AP）；BASE = 基本可用 + 软状态 + 最终一致。
  6. 云数据库 = 部署并虚拟化在云中的数据库，八特点（弹性、高可用、多租户、低成本、易用、高性能、免维护、安全）；无专属数据模型。
  7. UMP：七角色（Controller / Proxy / Agent / Web 控制台 / 日志分析 / 信息统计 / 愚公）+ 四组件（Mnesia / LVS / RabbitMQ / ZooKeeper）+ 七功能（容灾 / 读写分离 / 分库分表 / 资源管理 / 调度 / 隔离 / 数据安全）+ 四原则。
🎯 6 学时分配：①数据库概念 + NoSQL 由来 1 学时；②四类分类 + 与关系库对比 1.5 学时（单选/简答主战场）；③CAP/BASE 1 学时；④云数据库概念特点与产品 1 学时；⑤UMP 架构 1.5 学时（本章难点，按七角色 + 四组件 + 七功能三张清单背）。⚠️ 教材 5.5、5.6 不考，云数据库看教材 5.7 节。
